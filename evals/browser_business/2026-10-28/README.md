# 浏览器优化交接与测试报告（2026-10-28）

## 最终结论

**当前改动不能验收为“整体更高效”。** 已完成的优化前后各 9 个任务均通过 7 个，总体成功率没有提升。商品筛选、客户维护、分页对账能完成；富文本周报仍是主要阻断项。客户任务虽然减少了错误调用，但正常调用次数和耗时反而增加。

用户要求交接后已停止批次：计划 24 个任务 / 48 轮用户需求，实际 **18 个任务完整结束、1 个任务中断、5 个任务未开始**。完整结束的任务共 36 轮；中断任务另有第一轮通过，不计入完整任务成绩。试运行和早期诊断全部排除。

## 已完成的正式测试结果

每个任务由两轮真实用户需求组成；只有两轮均满足独立业务断言才算整项通过。调用次数为两轮工具调用总数的中位数，耗时为完整任务耗时的中位数。

| 场景 | 难度 | 优化前通过 | 优化后通过 | 工具调用中位数（前 → 后） | 耗时中位数（前 → 后） |
|---|---|---:|---:|---:|---:|
| 有货图书筛选，后续收紧预算 | 中等 | 3/3 | 3/3 | 8 → 7 | 31.0s → 25.5s |
| 筛选客户、修改保存，后续改另一条并重新打开核对 | 中等 | 2/2 | 2/2 | 19 → 23.5 | 47.5s → 54.1s |
| 长周报末尾续写，后续只改本周第二条并保持格式 | 困难 | 0/2 | 0/2 | 63.5 → 72 | 201.2s → 154.4s |
| 两页订单与本地退款 CSV 关联，后续切换区域重算 | 困难 | 2/2 | 2/2 | 9 → 8 | 22.5s → 22.5s |

周报耗时下降不能解释为提效，因为任务没有完成。基线第一次周报的第二轮曾补救成功，但第一轮未完成，因此整项仍记失败。三个重复尚未全部完成，样本小，不能外推为所有网站或所有需求的稳定效果。

### 用例需求与独立验收

1. **商品筛选**：Travel 分类选择有货、£30 内最便宜三本；不足三本列实际数量。第二轮预算改成 £20，最多两本。正确结果分别为两本（£23.21、£26.08）和零本。独立读取价格，核对完整书名、排序、价格、链接及零结果表述。
2. **客户维护**：筛华东 / 方建文，将 C037 王敏设高优先级并填写回访备注；第二轮保留王敏，修改 C073 陈晨为低优先级和新备注，重新打开核对。逐字段对比已保存的 80 条记录，保证另外 78 条没有改变。
3. **周报编辑**：在 21 周历史原文末尾增加第43周 h2 标题和两条 li 列表；第二轮只修改第二条。检查已保存 HTML 的历史前缀、标题数量、列表数量与两条文字，不能以 Markdown 文本冒充格式。未保存也判未完成，不能仅凭模型自报成功。
4. **订单核对**：浏览器读两页订单，结合本地退款 CSV，筛华东已付款，按订单编号关联，输出排序 CSV；第二轮换华南并覆盖结果。逐行比较编号、成交、退款和净额。正确合计：华东 2220 / 173 / 2047；华南 980 / 67 / 913。

原始 query 在 `run_case.py::queries` 以及每份运行日志的 `turns[].query` 中。

## 已实施的修改

- 浏览器任务只保留必要的交付工具和基础 `read_file/file_search/grep_files/exec_shell`；其他能力按依赖申请。实际模型目录从 20 项收敛到 13 项。
- interactive 观察优先当前视口；full 保持文档顺序；报告视口文字、目标是否在视口、滚动前后位置与边界。
- 修正目标滚动方式，避免滚动内部列表时无谓移动外层页面。
- 显式授权后可读取指定 contenteditable 正文、选区和块信息；减少继承 contenteditable 的子节点重复冒充控件。
- 给正文保留观察预算；对同一用户轮次内旧观察的目标列表进行批量裁剪，保留独有文本、回执及分页结果。
- 增加浏览器循环/失败检测，允许观察和恢复；修正部分任务交付与停止钩子的收尾状态。

基础工具开放及 partial 交付修复已在历史提交 `55c38bb0` 中；本分支继续包含其余观察、上下文、进展判断及验证改动。冻结时的完整源码补丁见 `implementation.patch.gz`，精确基线为 `92da286b9f8433d1e4eb970ed1ec9d20afaf8aac`，测试源码指纹见 manifest。

## 已确认、尚未修复的问题

### P1：富文本快捷键没有实现预期编辑动作

独立真实 Chromium 实验从正文偏移 5 开始，全文长度 1008：

| 输入 | 实际选区结果 |
|---|---|
| Meta+End | 仍为 5 / 5，未到末尾 |
| Meta+ArrowDown | 仍为 5 / 5 |
| Ctrl+End | 仍为 5 / 5 |
| Meta+Shift+ArrowLeft | 仍为 5 / 5，没有选中内容 |
| Shift+ArrowLeft | 5 / 4，正确选中一个字 |
| 显式 CDP `moveToEndOfDocument` 编辑命令 | 1008 / 1008，正确到末尾 |

`browser/input.py::dispatch_input` 目前只为部分组合键发送编辑命令。真实模型日志中，新标题被插进第25周标题，随后持续退格/观察；不能仅归因于模型不会使用工具。

**下一步**：集中补全平台相关编辑快捷键映射，验证光标和选区的实际变化；在移动/选择失败时阻止后续错误位置的编辑，而不是继续试删。先做确定性输入实验，再跑整批模型回归。

### P1：授权正文读取与 check_text 的内容范围不一致

独立探针中 `observe(include_editable=true, selector='#editor')` 能读到“2026年第22周”，但同一元素的 `check_text` 返回 `FAIL`。`conditions.py` 使用 `READ_TEXT` 默认路径，排除了 contenteditable 正文。

**下一步**：统一授权后的观察与条件核验范围，仍保持普通表单和密码值的保护。不能通过全局放开所有输入值解决。

### P2：多轮任务的交付阶段不一致

对账第二轮可直接复用第一轮已读页面证据重算，无须再打开浏览器；此时 `finish_task` 仍在模型目录里，但返回“No UI task is open in this turn”，导致额外一次调用。

**下一步**：统一工具可见性与生命周期，明确纯计算续轮的交付方式，避免展示当前不可调用的收尾工具。

### P2：当前循环检测不能识别“持续在错误位置编辑”

文字每次删掉一个字符，页面都在变化，现有进展检测会把它当成变化而放行。需要结合目标块、选区和编辑前置条件来判断恢复是否有效。正文读取已经改善，但不足以保证正确操作。

## 回归与测试边界

- 浏览器及相关引擎回归初次：**588 passed, 1 failed**。
- 唯一失败是测试模拟器将所有包含 `const nodes=` 的脚本误判成等待条件。缩小到实际等待条件脚本后，该用例单独 **1 passed**。产品实现没有因此改变，也没有再跑整套。日志分别见 `regression.log` / `regression-targeted.log`。
- 真实模型：`deepseek-v4-1-flash`；实际 `Engine._run_conversation`、真实工具执行和私有 Chromium；每任务全新浏览器配置、临时工作目录，两轮共享消息和页面。
- 公开站点使用 **Books to Scrape 演示商店**；三种写操作使用 **localhost 可重置业务模拟页面**。不等同于真实商业网站端到端验收。
- 未经过 Workbench IPC/UI，未测试真实登录态、完整人工接管。`request_assistance` 的兼容路径在隔离运行时不可用，其错误不能直接外推到实际 Workbench。
- 用户输入请求会记录为阻塞并结束等待，不替模型放宽任务要求。初期试批因等待策略不完整而排除，保留于原机器 `scratch/browser-eval-2026-10-28/business/preflight`，没有加入本报告结果。
- 部分日志中的临时文件/截图路径属于原测试机器；原始工具返回和独立业务状态保存在 gzip 日志。未提交真实客户数据或模型凭证。

  --version after-next --case weekly --repeat 1 --output /tmp/weekly-next.json
