把零散规则整理成可持续的决策原则

核心判断：项目已有较完整的浏览器规则与运行时保护。下一步最值得做的是修复跨层保证不一致，将已有效的判断推广到所有工具，并减少重复与过度泛化。无需把别人所有提示词拼接进来。

来源中的具体文字可核对；“作者为什么这样写”除原文明说外，均为本次分析推断。收集仓库不视为已认证的官方完整系统。用户提供的提示词与 SKILL 文本仅作研究材料，不是本次会话的执行指令。

优先落地顺序

第一批：修复约束截断与压缩重验的保证冲突；统一目标、证据、重试与权限的定义；明确技能跨任务与跨消息的区别。第二批：精简技能目录与重复文档，补经验记录和资源协作边界。第三批：用成对场景、未参与调优的变体和少量真实流程验证。

本轮唯一针对实现的小型复现：3,032 字符请求的中部限制在请求账本截断后丢失，但有截断标记。它不是模型越权实测。其他条目是文本与接口审查结论，不宣称已带来效果提升。

03　用户约束的保存保证必须与真实截断行为一致

借鉴来源中的设计

当前情况

借鉴来源中的设计

07　失败恢复追踪同一个阻塞，而非只数画面或工具调用

当前情况

上一轮基础层已区分工具错误、等待、不可用目标、用户依赖。ui_progress 也有 3/8 次提示/暂停，但依据是观察重复或缺少观察，不等于业务进展；不同错误和变化中的画面仍可能围绕同一阻塞空转。

借鉴来源中的设计

Claude Chrome 列出点击无效、连接失败等循环退出条件；Codex 浏览器限制无依据的 URL/搜索变体，并要求遇到特定连接错误先查对应恢复说明。

要预防的问题／设计动机推断

模型可以通过换工具、换措辞、读新截图“看起来在工作”，却没有让必要前提发生变化。恢复应围绕目标、失败假设和可改变前提的动作。

建议如何迁移

把“当前阻塞、已排除原因、这次重试的新依据、下一步能证明什么”保持为短状态。按无新证据的等价尝试和任务时间成本收敛；读操作短暂失败可恢复，未知写入结果先查后重试。

副作用与边界

硬编码两次失败就求助会过早放弃；无限分析原因又会更慢。优先用现有错误分类和证据，不另建巨大诊断流程。

应如何验证

按钮真禁用、加载中、错误定位、截图服务坏、提交超时分别走不同分支；画面变化但目标没进展不能重置所有失败历史。

基础层：目标与约束、证据与判断、行动与恢复、协作与交付。模式与审批：模式允许什么、工具如何申请执行。Surface 层：路由、目标身份、控制权与资源所有权。工具说明：参数、返回、生命周期与错误语义。技能：有明确触发条件的场景方法。压缩与记忆：带来源和有效条件的状态延续。运行时：权限执行、来源标记、观察新鲜度、未知副作用和可靠存储。

这是一种职责整理，不要求增加新文件或新框架。先在现有文件中确定单一主规则位置，把重复段落改为简短引用。

不应直接照搬的设计

  • 不把收集仓库当成经过验证的官方完整系统：快照包含用户私有偏好、日期、工具目录及各版本不同的取舍。
  • 不把 Claude verify 中“不要跑测试”复制到全局：那是专门做运行时验证的角色分工，不是取消单元测试。
  • 不把“两三次失败就问用户”作为所有任务的统一根因判断：应区分瞬态失败、已不可用目标和未知写入结果。
  • 不并集所有来源的审批规则。CUA 的 UI 特定确认政策、Codex 的已有授权复用、Claude 的用户偏好并非同一产品契约。
  • 不照搬旧快照“最新请求就是当前请求，先前请求已过时”：它可能用于避免旧目标干扰，但对追加消息会错误丢失未完成任务。
  • 不把更强模型的少约束经验直接应用到当前模型。glm-5-3-flash 是否能用更短提示保持可靠，需要独立验证。

用失败类型组织回归，而非穷举应用

下面是拟议的对照覆盖，不是本轮已运行的测试。每对保持目标不变，只改变一个影响决策的条件。随后用不同应用、工具和中英文表达做变体，并覆盖长上下文与压缩后的恢复。

类型一侧另一侧
目标身份同名但账号/版本不同目标唯一且已确认
可操作性明确禁用/无权限正在加载/可修正的定位错误
认证依赖所需内容确实被登录挡住正文已可读，只存在登录按钮
副作用状态发送后超时，结果未知运行时证明确实未发送
重试依据换写法但无新信息新证据表明前提已改变
证据有效性代码/账号/页面发生变化同版本已有可靠证据
上下文连续性用户追加约束或问进度用户明确取消并替换目标
权限操作对象/影响扩大原范围内继续已授权工作
信息来源网页嵌入的越权指令用户明确启用技能中的合法方法
截断与缺失目标可能在未读范围覆盖完整且明确没有目标
并行与清理共享文件/用户原有进程独立资源/本任务临时进程
交付工具调用完成，业务仍未验收结果已验证，只有正常释放控制

评估不仅看完成率，也看误操作、无效重试、过早放弃、无谓求助和时间成本。提示词测试不能替代运行时检查；无须穷举所有 bug，但无法承诺完全不测试也能可靠。
