## 十轮对照页面为什么答对了还要六分半

复核的是此前同一需求的[成功复测](../../scratch/personal-sessions-compare-retry/scorecard.md)。以下按归档产品回合计时，不是评分耗时。把有 tool_name 的调用区间裁到回合内并取并集，并发工具不重复累加。余量包含准备请求、等待模型、生成回复及运行时处理；现有事件没有把它们可靠分开。

| 回合 | 工具次数 | 回合用时 | 至少一个工具正在执行 | 其余时间 |
|---|---:|---:|---:|---:|
| 先做十轮页面 | 29 | 90.5 秒 | 8.5 秒 | 81.9 秒 |
| 只改客户，导出 JSON，现场查看 | 38 | 303.2 秒 | 89.3 秒 | 213.8 秒 |

两轮共记录 71 个模型轮次。第二轮首请求保留前序消息，同时明确送入角色纠正。第 1 至 4 次调用读生成器、修改、重建并检查 JSON。第 24.7 秒已有可复核的结果：两份各十轮，字段相同，客服全部一致，客户十条均改写。

- **24.7 至 100.9 秒。** 开始检查能否实际打开页面。第 5 个调用把启动本地 HTTP 服务与 Chrome 截图写在同一条 Shell 命令中，工具返回文本明确记录 60 秒超时。仅凭组合命令无法分辨内部哪一个子进程卡住。后续复核修正了真实导航错误：原生成器把整条记录放入锚点，改为取轮次编号，重建后检查 nav。第 25 秒后仍有必要工作。
- **100.9 至 136.4 秒。** 检查渲染、长页和展开态。连续三次读取同一张长图分别裁了底部、中段和顶部，观察区域不同，不能按相同文件名直接算重复。
- **136.4 至 303.2 秒。** 剩余约 167 秒，20 个工具调用。为满足现场打开的要求，尝试 CUA、默认浏览器、系统截图和浏览器窗口查询；多条路径返回错误，最后又回到 JSON 与 HTML 检查。这一段没有改进归档页面或数据，也没有取得用户前台成功打开的可靠证据。首次尝试能检验用户要求，多个失败通道间切换以及重复核对已验证数据，值得重点抽审。

对照第一次限时运行，首轮 180.4 秒内有 58 次工具调用，工具执行区间合计 15.3 秒，其余约 165.1 秒；第二条用户纠正尚未送达。两次共同出现的是验证步骤多、每一步还要进入下一轮决策。仅成功复测出现一个占 60 秒的调用。不能把所有慢都归因于截图或接口延迟。[首试评分卡](../../scratch/personal-sessions-pilot/scorecard.md)

## 开放式任务：让 agent 出一份能用的测评集

第六题来自 Codex 会话 48d6b4c0。真实需求是之前的问题太相似，需要挑代表并补复杂题。本次给出四种机制的本地候选池，要求产出可验收的 cases.json。Flash 用了 68.8 秒、17 次工具调用，工具执行区间仅占 1.4 秒。第一次 read_file 已返回完整四行，随后再次读文件，又用 cat、wc、od 检查同一内容。第一次落盘后验证 JSON 和验收点是合理的；自写检查又要求某些题有至少五个检查项，触发失败后反复补条目，这个数量门槛来自模型自己的脚本。增加条数没有解决下述验收冲突。

产物用 A2 代表三种同义查人请求，并选了对账、用户纠正、提交结果未知，新增多步发布中途失败。费用表可以复算。评测端原本硬性要求 oracle 是字符串且至少选三种现有来源，但题面没有这两项限制。实际 oracle 是带 setup、pass、fail、checks 的对象，首轮误判失败。放宽这两项后，用原产物和原裁判重评通过，没有二次请求模型。[原评分](../../scratch/personal-breadth-portfolio/scorecard.md) · [重评](../../scratch/personal-breadth-portfolio/regrade-20261106-083240/scorecard.md)

**人工审核结论为部分可用。** 草稿题一处把“先发布再存草稿、留下对外痕迹”写成失败，另一处允许第一轮已经发布、第二轮撤下再存草稿。对于曾公开但已撤回的同一轨迹，验收人需要知道纠正何时到达、是验当前可见性还是曾经公开。自动语义裁判放过了这一点。本批六份产物重评后均被自动放行，人工复核是五份可用、一份需修订。[五道生成题的原始交付](../../scratch/personal-breadth-portfolio/sessions/personal.eval_portfolio-ca0c6c7c/workspace/cases.json)
