## 哪些问题会误导决策

1. **串行试验也能互相读取。** 初版卡片题第一次运行时，Shell 成功读取兄弟工作区的两份 AGENTS.md 和共用 server.log。观察到的是说明和日志；没有证据表明读到了答案。整批排除出正式 A/B。做封存评估前，以每次试验为单位隔离文件系统，评审、答案和凭据置于 Agent 工具可读范围外。验收隔离时可在相邻试验与评审目录放不同的随机标记，通过 shell 和文件工具尝试读取。仅改目录名或改成串行无法通过这个测试。
2. **有结束记录的任务仍可能没有质量标签。** 11 月 4 日 Browser/CUA 批次共选 588 题，444 题环境阻塞，135 题在运行汇总中标记为 completed_ungraded。应分别显示总题数、可运行数、已有终态验收数和已验收题中的通过数。第一次卡片试验的回合状态同样为 completed，文件却保持原样。[运行汇总](../artifacts/browser-cua-deepseek-v4-1-flash-20261104/analysis_summary.json)
3. **有些检查能被空产物满足。** 按原样发放所有输入，用空答复、零工作测试 22 道 daily_tasks。其中 5 道的题目级事实检查没有一项失败，含 2 道无此类检查。用 daily.orders 的三份输入再加一个零字节 irrelevant.txt，两项事实检查全部通过，包括“有可处理的清单文件”。最终裁判另有语义评审与会话检查。对账题值得写的硬断言，是读回处理清单，确认 A02 的 60 元差额、重复收款和退款后状态。[题目](../suites/daily_tasks/live.yaml) · [验收器](../rubric.py)
4. **版本归因与计量存在缺口。** 比较器会检查题集、评分器、重复次数和若干预算，但 judge_provider、并发、输入 token 上限不在其可比条件中。grader_hash 没覆盖参与判定的 session_metrics.py。修订卡片题实际有 5 个会话轮次，usage.requests 仅记 1，priced_requests 为 0。评审请求、Agent 请求、预检和计费覆盖应分别显示。旧报告的总体 53.0% → 73.3% 同时伴随端点、沙箱、超时和输出上限变化，8 道封存题的 +5.6 个百分点在其噪声范围内。[比较器](../experiments.py) · [manifest](../runner.py) · [历史报告](2026-11-01-holdout-audit.md)

## 建议的评估流程

**建题。** 按一个可验收的用户目标切分历史。每题记录来源摘要、初始工作区、当时用户可见的信息、后续纠正、允许的副作用、独立验收证据、任务族和版本。成功任务与用户投诉分层抽样，保留分母。原助手的最后一句和工具路径只供复盘。缺截图、远端状态或账户时标明缺什么；可重建的意图用合成夹具，单独记录与原任务的差距。

**分集。** 同一个原始会话、同一问题的连续反馈、同模板变体按任务族归在一起。频繁重跑的放开发或回归集。另预先冻结从未用于调优的任务族、评分版本和预算。看过失败轨迹并据此修改产品的题转入回归集，下次泛化判断另取封存题。公开基准作为外部分布单列。

| 维度 | 如何验收 | 怎样校准这把尺 |
|---|---|---|
| 完成质量 | 实际运行代码、读回产物、检查页面或服务终态 | 给空产物、错一个关键值的产物和有效替代解 |
| 授权与副作用 | 核对请求 ID、实际执行动作、受保护文件差异 | 批准 A 后尝试执行 B，同时允许合法替代工具 |
| 跨轮、中断与恢复 | 在确定的工具事件后注入纠正，检查新约束落实、原目标继续、动作未重复 | 同一任务分别正常完成和中断后继续 |
| 如实度和协作 | 将完成声明逐项对应工具返回或产物；人工盲审一部分分歧 | 把正确求助、过早求助、虚报完成分开标注 |
| 稳定性与代价 | 首次成功率、多次均成功的比例、耗时、token、人工介入、计费覆盖 | 环境故障和评审故障另列；区分一次成功与多次尝试后成功 |

**判断一次优化。** 动手前写清目标任务族、应改善的可见结果和禁止退化项。先做同版本 A/A 测自然波动，再在固定端点、权限、预算、夹具和裁判下交错跑基线与候选。试点可从每题每版本 3 次起步，按波动补样；列出逐题族分子、分母和配对差异，按任务族估算区间。重复试验不增加独立任务族数量。出现污染标记试验无效；出现关键权限回归单列；效果低于噪声则保留原结论，继续采样。通过率以外同时查看虚报、人工介入和成功任务成本。

**下一批优先选什么。** 先关闭跨试验可读并使空文件反例失败，然后补三个真实工作流。分支同步用一次性本地 bare remote 验收目标提交和未提交改动；浏览器运行中插话用可重置页面和固定事件注入纠正；授权后恢复用可模拟批准的环境核对最终动作与重复执行。三类均应先有已知好解和坏解，再运行模型。现有产品 harness 全局禁止 Git 提交，测用户明确授权的 Git 工作流时需按题配置边界。

这里区分轨迹与终态、组合程序判分和校准过的评审，参考了 Anthropic 的实践。隔离反例和空文件反例均来自本仓实测。[Demystifying evals for AI agents](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)
