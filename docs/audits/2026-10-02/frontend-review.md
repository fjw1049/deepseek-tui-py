## 1 审核结论

目前不宜直接认定系统已经达到“长时间使用流畅、复杂操作稳定”的目标。最先需要解决的是编辑内容可能丢失、看板任务可能发到错误会话、自动化通知选项被覆盖，以及发送消息时突然渲染全部历史。这些问题比进一步调整动画曲线更影响体验。

本轮按下表 31 个功能模块完成了代码与调用链审核，并运行了类型检查、测试、构建、针对性复现和 Git 服务小型基准。发现 15 项功能或交互问题、7 项需要控制的性能风险，以及构建质量检查未通过的问题。部分问题已经用隔离测试复现，其余明确标为静态调用链确认或条件风险。

没有进行真实 Electron 窗口的完整点击回归，也没有录制 CPU、内存、输入延迟或帧率曲线。因此，本报告不把“可能卡顿”写成已经测得掉帧，也不把未发现缺陷的模块视为绝对没有问题。涉及真实账户、语音设备、外部渠道、模型服务的端到端行为，需要按最后的验收方案补测。

### 判断标准

- **P1：优先修复。** 涉及内容丢失、错误执行、用户明确选择失效，或主要使用路径的大规模额外渲染。
- **P2：随后修复。** 特定操作、数据规模或异步时序下出现错误；或有明确结构性性能风险。
- **已复现：** 隔离测试触发了当前错误行为。测试通过表示成功证明问题存在，不表示问题已修好。
- **调用链确认：** 已核对入口、状态更新和下游消费者，但没有在真实桌面窗口复现。
- **性能风险：** 实际代价取决于数据量、设备和使用时间，修复前后应使用同一场景测量。

## 3 功能与交互问题

### F01 P1 切换项目会直接清空未保存的编辑内容

**证据：已复现。** [工作区重置逻辑](/Users/fjw/Desktop/deepseek-tui-py-main/packages/workbench/src/renderer/src/store/workspace-editor-store.ts:212)在工作区发生变化时清空全部标签；[编辑器面板](/Users/fjw/Desktop/deepseek-tui-py-main/packages/workbench/src/renderer/src/components/workspace-editor/WorkspaceEditorPanel.tsx:781)会在根目录变化时调用它。现有关闭标签的保存提示没有覆盖这条路径。

复现顺序：在项目 A 打开文件并修改但不保存 → 切到项目 B → A 的标签与内存草稿被清空。隔离测试验证了 dirty 标签直接变成空列表。

**修复建议：** 在工作区切换入口统一处理未保存文件，提供保存、放弃、取消；或按工作区保留可恢复草稿。只加关闭标签提示不够。

**验收：** 项目切换、worktree 切换、由不同项目会话触发的根目录变化都不能静默丢失内容；取消切换后原编辑状态完整保留。

### F02 P1 外部刷新旧响应可以覆盖刚保存的新内容

**证据：已复现。** [reloadCleanTabs](/Users/fjw/Desktop/deepseek-tui-py-main/packages/workbench/src/renderer/src/store/workspace-editor-store.ts:487)发起读取时只选干净标签；响应回来时也只检查当前是否 dirty，没有比较读取前后的内容版本。

复现顺序：后台开始读取旧内容 → 用户修改并保存新内容，标签重新变为干净 → 较晚返回的旧读取结果覆盖 `content` 和 `savedContent`。测试已验证编辑器回到旧文本。此时不等于磁盘立即被覆盖，但后续编辑保存可能把旧版本重新写回。

**修复建议：** 对标签维护编辑/保存版本或请求序号；仅允许请求期间未变化的快照写回。工作区身份也应包含生命周期代次。

**验收：** 人为延迟文件读取，同时编辑并保存；旧响应必须被丢弃，新文本和已保存状态保持一致。

### F03 P1 看板创建或选择会话失败后仍可能向当前会话派发任务

**证据：调用链确认。** [看板新建与派发](/Users/fjw/Desktop/deepseek-tui-py-main/packages/workbench/src/renderer/src/components/kanban/KanbanView.tsx:246)等待 `createThread` / `selectThread` 后，读取全局当前会话或直接调用全局发送。[createThread](/Users/fjw/Desktop/deepseek-tui-py-main/packages/workbench/src/renderer/src/store/chat-store.ts:2165)会捕获错误，调用方无法把正常完成与失败区分开；选择失败或选择请求被更新请求取代，也不能保证当前会话就是目标会话。

例如当前在 A，会话 B 的草稿派发过程中读取 B 失败，调用方仍继续发送，就可能把 B 的任务交给 A。快速交叉派发也有类似目标身份风险。若任务会修改文件，影响不仅是显示错位。

**修复建议：** 创建/选择返回明确成功结果与目标 ID；派发必须绑定该 ID。[sendMessage 已支持 expectedThreadId](/Users/fjw/Desktop/deepseek-tui-py-main/packages/workbench/src/renderer/src/store/chat-store.ts:2520)，优先使用现有能力，并在异步边界校验目标身份。失败时保留草稿，不继续发送。

**验收：** 注入创建失败、选择失败、A/B 交叉点击和操作中切换会话；任何情况下都不能发送到错误会话。

### F04 P1 自动化选择不投递会被默认渠道自动改回

**证据：已复现。** [投递默认值 effect](/Users/fjw/Desktop/deepseek-tui-py-main/packages/workbench/src/renderer/src/components/automation/AutomationTaskForm.tsx:132)只要发现 `none` 且目标为空，就重新设置已配置的飞书、企业微信或邮件渠道。用户主动选择“不投递”也满足这个条件。

测试在已配置飞书默认目标的情况下选择 none，状态会变回飞书。这会违背用户对外部通知的明确选择。

**修复建议：** 默认值只用于新建表单的首次初始化；区分“尚未选择”和用户主动选择 none，编辑已有配置时也不得覆盖。

**验收：** 每一种默认渠道下都能选择并保存“不投递”；重新打开仍为不投递，执行时不发送外部通知。

### F05 P2 单次自动化编辑时没有还原原执行时间

**证据：已复现。** [表单初始状态](/Users/fjw/Desktop/deepseek-tui-py-main/packages/workbench/src/renderer/src/components/automation/AutomationTaskForm.tsx:85)把已有自动化默认设成 custom，而单次任务的 `schedule` 为空；`onceAt` 也没有从原 `run_at` 还原。

结果是单次任务打开后显示空的自定义周期，单纯改标题也可能遇到 cron 必填错误；手动切回单次后又可能使用新的默认时间。

**修复建议：** 按单次与周期任务分别初始化，并保留原始执行时间及其时区含义。

**验收：** 创建未来时间的单次任务 → 重开只改标题 → 保存；执行时间和类型完全不变。补测已经执行过的单次任务。

### F06 P1 长对话在发送时突然挂载全部历史

**证据：已复现。** [消息时间线](/Users/fjw/Desktop/deepseek-tui-py-main/packages/workbench/src/renderer/src/components/chat/MessageTimeline.tsx:512)在 busy 时把可见轮次数增大到全部历史。虽然初始超过阈值时只显示最近 18 轮，但发送后失去这一限制。

40 轮对话的组件测试中，空闲时挂载 18 轮，busy 后挂载 40 轮。更长历史意味着 Markdown、代码和消息组件在开始生成时集中挂载，恰好与流式更新争用主线程。测试证明挂载增长，未测量实际掉帧数。

**修复建议：** 保证最新一轮始终显示，同时继续约束旧消息挂载量；采用有边界的历史窗口，必要时做适合变高消息的虚拟列表。

**验收：** 1,000 轮历史发送消息时，已挂载旧轮次数不应突然增长到全量；滚动位置、继续加载历史、流式跟随和代码复制均正常。

### F07 P2 查询轨迹无法跳到尚未挂载的旧消息

**证据：已复现。** [定位处理](/Users/fjw/Desktop/deepseek-tui-py-main/packages/workbench/src/renderer/src/components/chat/MessageTimeline.tsx:443)直接查找 DOM 节点；找不到时仍清空定位请求，没有先补载对应历史。

测试点击未挂载的最早消息，目标仍不存在，定位请求却已经被清除。用户感觉点击没有反应。

**修复建议：** 先通过消息 ID 计算目标轮次、展开所需窗口，等节点挂载后再滚动；定位成功或确定目标不存在后才结束请求。

**验收：** 查询轨迹与历史导航均能定位最早一轮、窗口外消息和刚完成的消息，并有明确的不存在状态。

### F08 P2 隐藏终端后重开可能丢失输出历史和关闭期间的输出

**证据：调用链确认。** [Workbench 的条件挂载](/Users/fjw/Desktop/deepseek-tui-py-main/packages/workbench/src/renderer/src/components/Workbench.tsx:1982)会在关闭底部面板时卸载终端；[终端清理](/Users/fjw/Desktop/deepseek-tui-py-main/packages/workbench/src/renderer/src/components/AppTerminalPanel.tsx:378)释放 xterm 实例及订阅。底层 PTY 会话却可以继续运行，而当前主进程转发没有为重新挂载提供完整输出重放。

因此重新打开旧会话可能得到空白显示，隐藏期间产生的输出也不能补回来；关闭期间的退出事件同样需要检查状态同步。

**修复建议：** 将终端会话和输出缓冲的生命周期独立于面板显隐。可保留终端实例并重新附着，或提供有大小上限的主进程缓冲及重连快照。

**验收：** 连续输出时隐藏 10 秒再打开，既有历史与期间输出可见；隐藏期间退出后状态正确；真正关闭会话才释放资源。

### F09 P2 正在读取的文件关闭后会被旧响应加回状态

**证据：已复现。** [文件读取完成后的写回](/Users/fjw/Desktop/deepseek-tui-py-main/packages/workbench/src/renderer/src/store/workspace-editor-store.ts:307)检查工作区，却通过 upsert 写入标签，没有确认该次打开仍然有效。

测试在读取未完成时关闭标签，随后响应回来，`tabs` 再次出现该标签，但主标签顺序中没有它，形成残留状态。

**修复建议：** 文件打开操作持有代次或令牌；关闭即失效，只有仍存在且令牌匹配的 loading 标签可以接收结果。

**验收：** 延迟打开后立即关闭、关闭后重新打开、A→B→A 工作区切换，都不产生幽灵标签或旧内容回填。

### F10 P2 自动化运行记录切换存在旧请求覆盖新选择的风险

**证据：调用链确认。** [refreshRuns](/Users/fjw/Desktop/deepseek-tui-py-main/packages/workbench/src/renderer/src/components/automation/AutomationCenter.tsx:228)直接将异步结果写到共享 `runs`；切换选择会发起新读取，没有将响应和当前自动化身份绑定。

A 请求慢、B 请求快时，可能先显示 B，再被 A 的运行记录覆盖，形成标题与列表不一致。

**修复建议：** 按自动化 ID 存储记录，或使用请求序号和当前选择校验；loading、错误状态也必须同样隔离。

**验收：** A 延迟 2 秒、B 延迟 100 毫秒，快速切换后最终只能显示 B 的记录和错误状态。

### F11 P2 超过 100 个任务后旧的运行中任务可能从状态索引消失

**证据：调用链确认。** [任务索引读取](/Users/fjw/Desktop/deepseek-tui-py-main/packages/workbench/src/renderer/src/hooks/use-thread-tasks.ts:143)以及同文件的状态刷新，取全局 `/v1/tasks?limit=100` 后再本地筛选。后端按创建时间排序截断，所以正在运行并不保证能进入最近 100 条。

持续运行的老任务遇到大量新任务时，侧栏活动提示、看板分类或运行状态刷新可能缺项。不同界面的缓存策略决定具体表现，不能统一断言全部任务都会显示完成。

**修复建议：** 后端按活动状态过滤后再分页，或按可见线程/已知任务 ID 批量查询；不能用最近 100 条代表全局活动集合。

**验收：** 构造 101 条以上任务，其中最老一条仍在运行；侧栏、看板及详情都能持续更新它的状态。

### F12 P2 大段文本粘贴完成后可能覆盖附件或回填到错误会话

**证据：调用链确认。** [handleLargePaste](/Users/fjw/Desktop/deepseek-tui-py-main/packages/workbench/src/renderer/src/components/chat/FloatingComposer.tsx:1331)等待文本落盘后使用捕获的 `attachments` 追加附件，缺少函数式更新和目标会话校验。

两次快速粘贴、等待期间删除附件，可能被旧数组覆盖；等待期间切换会话还可能把附件回填到新上下文。相邻图片添加路径已有目标身份保护，说明可以沿用现有做法。

**修复建议：** 使用函数式附件更新，同时捕获并验证会话/工作区代次；过期操作不更新当前会话，提供处理中状态。

**验收：** 两次并发粘贴都保留、等待时删除的附件不复活、切换聊天后不出现上一个聊天的附件。

### F13 P2 同路径 HTML 和图片预览缺少更新版本信号

**证据：调用链确认。** [HTML 预览](/Users/fjw/Desktop/deepseek-tui-py-main/packages/workbench/src/renderer/src/components/workspace-editor/HtmlDocumentPreview.tsx:51)与[图片预览](/Users/fjw/Desktop/deepseek-tui-py-main/packages/workbench/src/renderer/src/components/workspace-editor/ImageDocumentPreview.tsx:51)依赖路径和根目录；同路径内容更新没有明确驱动 iframe 或图片重新加载。现有编辑器刷新主要处理文本标签。

结果是在外部工具或代理修改文件后，预览可能继续显示旧内容。不能把这一结论推广为所有网页都无法热更新：接入自身 HMR 的开发页面是另一条路径。

**修复建议：** 文件变更传递版本号或明确的刷新事件，更新预览资源；需要保留页面交互状态时提供显式刷新提示。

**验收：** 同一路径修改本地 HTML 和 PNG，不关闭标签也能得到新内容；另行检查 PDF 等同类预览，避免漏掉不同实现。

### F14 P2 模型设置刷新列表会提前保存密钥，取消不能撤销

**证据：调用链确认。** [refreshModels](/Users/fjw/Desktop/deepseek-tui-py-main/packages/workbench/src/renderer/src/components/settings/LlmProvidersPanel.tsx:1145)在获取模型前调用 `setSettings` 写入当前密钥；但同一表单仍有独立的取消和保存按钮。

**修复建议：** 模型探测接口接受临时密钥参数，只有保存动作持久化；避免通过临时修改全局设置完成探测。

**验收：** 修改密钥后刷新成功或失败，再取消，原密钥均保持不变；确认保存后才切换密钥。

### F15 P2 邮件配置可能以旧快照覆盖其他配置修改

**证据：条件风险，调用链已确认。** [邮件配置](/Users/fjw/Desktop/deepseek-tui-py-main/packages/workbench/src/renderer/src/components/channels/EmailChannelSetup.tsx:71)先保存整个配置文本，提交时基于旧文本更新邮件字段并写回；[配置写入接口](/Users/fjw/Desktop/deepseek-tui-py-main/packages/workbench/src/main/ipc/register-app-ipc-handlers.ts:944)直接写入传来的整份配置。

**修复建议：** 主进程读取最新配置后只合并邮件字段，并串行/原子写入；或者检查文件版本冲突并要求重新载入。

**验收：** 打开邮件表单后从另一入口修改非邮件字段，再保存邮件；两个修改都保留，不允许静默回退。

## 4 性能风险与优化依据

### R01 P2 Git 列表读取提前生成完整差异，未跟踪文件重复扫描

[Git 变更入口](/Users/fjw/Desktop/deepseek-tui-py-main/packages/workbench/src/main/services/git-service.ts:704)获取列表时同时生成 combined、staged、unstaged 差异；未跟踪文件路径还会在不同差异集合中重复执行 patch 计算。需要简单状态的消费者也承担了完整差异成本。

隔离仓库基准：已有一个提交的仓库加入 200 个未跟踪文本文件，每个 20 行。空变更读取约 **11.3 ms**，加入文件后的首次完整读取约 **729.8 ms**，缓存命中约 **11.4 ms**。这是一次服务级基准，不是界面响应时间，也不能代表所有机器。它说明缓存失效后的成本值得优化，缓存正常时已有明显收益。

**建议：** 列表只取 status/numstat，选中文件才读取 patch；未跟踪文件计算复用；为大差异设置上限。验收时分别记录冷读取和缓存命中，不能只测连续点击的热缓存。

### R02 P2 高频流式状态仍可能带动工作台和输入区域重渲染

[Workbench](/Users/fjw/Desktop/deepseek-tui-py-main/packages/workbench/src/renderer/src/components/Workbench.tsx:303)订阅消息块、推理和 liveAssistant，后续还有内容/预览提取；[分屏聊天内容](/Users/fjw/Desktop/deepseek-tui-py-main/packages/workbench/src/renderer/src/components/chat/ChatSplitWorkspace.tsx:47)存在范围较大的 store 订阅。流式合帧能减少更新次数，但不能保证每次更新的渲染范围足够小。

**建议：** 先用 React Profiler 核实提交范围，再把流式订阅下沉到消息叶节点，收窄 selector；预览发现等非即时计算独立节流。不要为此整库重构或无差别添加 memo。

**验收：** 持续输出时输入文字、切换菜单和调整宽度，输入组件及无关侧栏不应因每个增量反复提交。

### R03 P2 关闭分屏后会话资源没有明确的容量上限

[chat-pane-sessions](/Users/fjw/Desktop/deepseek-tui-py-main/packages/workbench/src/renderer/src/store/chat-pane-sessions.ts:5)按会话保存实例；关闭一个可见 pane 不等于销毁会话，通常要线程删除/归档或整个工作台卸载才清理。这有利于后台任务延续，但大量打开再关闭的会话可能继续持有状态及订阅。

**建议：** 区分正在执行、有待发送队列与完全空闲会话；仅对空闲会话做有容量上限的缓存淘汰，保留恢复所需游标。不要直接关闭仍在运行的任务。

**验收：** 重复打开关闭 50 个空闲会话后，实例数、订阅数和内存趋于稳定；后台执行任务仍可恢复并显示完整结果。

### R04 P2 工作台与编辑器产物较大，存在启动和首次打开成本

本轮构建成功后的非 gzip 文件大小：Workbench 约 **2,595 kB**，AppShell 约 **530 kB**，WorkspaceEditorSurface 约 **7,349 kB**，另有较大的图表、语言等依赖块。编辑器为延迟加载，不能把所有文件相加当作首屏下载量；Electron 本地读取也不同于公网网页，但解析、执行和初始化仍有成本。

工作台同时引入多个功能页面，当前加载策略需要在“启动代价”和“首次点击等待”之间实测取舍。

**建议：** 按导航边界拆分低频功能，空闲时预取常用面板，保留明确的加载反馈；单独分析编辑器依赖和语言加载，避免为缩包损失必要功能。

**验收：** 分别测冷启动可交互、首次进入编辑器、再次打开、首次打开插件/自动化页面；不能只以构建文件变小作为完成标准。

### R05 P2 大差异与表格预览缺少足够的渲染规模限制

[差异视图](/Users/fjw/Desktop/deepseek-tui-py-main/packages/workbench/src/renderer/src/components/DiffView.tsx:358)会进行完整源码高亮，并映射大量行；[变更检查器](/Users/fjw/Desktop/deepseek-tui-py-main/packages/workbench/src/renderer/src/components/ChangeInspector.tsx:1270)涉及默认完整文件展示。主进程允许较大的差异读取，输入规模可明显超过适合同步高亮的范围。

[表格预览](/Users/fjw/Desktop/deepseek-tui-py-main/packages/workbench/src/renderer/src/components/workspace-editor/TableDocumentPreview.tsx:8)虽然有展示上限，但 500 行 × 50 列仍达 25,000 个单元格，而且先解析内容再限制展示。

**建议：** 大文件按体积/行数降级为上下文差异或纯文本，提供截断提示；表格限制解析工作量并虚拟化可见行。高亮是否迁到 worker，应以主线程耗时测量决定。

**验收：** 大型新增文件、长行、压缩 JSON、500×50 表格都不能长时间阻塞输入和关闭操作。

### R06 P2 浏览器隐藏标签仍保留页面运行环境

[浏览器面板](/Users/fjw/Desktop/deepseek-tui-py-main/packages/workbench/src/renderer/src/components/DevBrowserPanel.tsx:1285)保留隐藏 webview；暂停媒体和静音不等于停止任意页面脚本、请求和定时器。多个重型页面长期打开时可能持续消耗资源。

**建议：** 先测标签数对应的 CPU/内存，再考虑空闲标签休眠、容量提示和明确关闭行为。休眠必须处理未提交表单与恢复体验，不能只为省内存自动销毁用户操作。

**验收：** 打开 10 个包含脚本的页面，切到其他模块后测后台资源；关闭标签确实释放相应资源。

### R07 P2 部分轮询与批量读取缺少统一的并发边界

任务、连接器等多处定时刷新存在不同频率；部分采用固定间隔，而请求可能比间隔慢。自动化的[全量运行记录读取](/Users/fjw/Desktop/deepseek-tui-py-main/packages/workbench/src/renderer/src/components/automation/AutomationCenter.tsx:243)对全部条目并行读取，没有批量接口或并发上限。

不是所有轮询都有这个问题：部分运行详情和对话读取已经采用完成后再安排下次请求，应保留这种做法。

**建议：** 同一资源合并请求，前一次完成再安排下一次；页面不可见时降频，失败退避；批量运行记录使用后端聚合或有限并发。

**验收：** 把接口延迟设为 15 秒，观察 60 秒，同一轮询器在途请求不持续累积；100 个自动化不会瞬间发起无上限请求。

### 测试失败的归因

1. workspace-preview-server 的 8 个失败源于沙箱不允许监听端口。允许监听后原失败用例通过，不能记为预览服务器业务缺陷。
2. WorkspaceEditorPanel 两个失败发生在清理环境时，`window.localStorage.clear` 不可用；本机 Node 25.9.0 的 Web Storage 行为需要与测试环境一起校准。尝试关闭 Node 实验性 Web Storage 后，worker 中的问题仍存在，不能声称已经解决。
3. SessionHeader 测试缺少 `pinnedThreadIds` 状态；SidebarCollapseToggle 测试访问了不存在节点的 `className`，属于测试/实现契约待校准。
4. RunPanel 的 react-i18next mock 缺少 `initReactI18next`，导致套件初始化失败。
5. usage-ledger 用 2026-06-24 的固定模拟数据查询相对当前日期的 90 天窗口；到本轮日期数据已经过期。应固定时钟或统一传入 now，不能把日期漂移解释成真实统计必然失败。

**处理方案：** 固定团队支持的 Node 与测试环境；排除本地依赖残留目录；修复真实类型问题及测试契约；将 typecheck、lint、test、build 都纳入发布门槛。测试修复后再运行完整套件，不建议以永久跳过失败测试完成验收。
