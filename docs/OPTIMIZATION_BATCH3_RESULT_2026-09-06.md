# 第三批实施记录：停止、打断与恢复权限

日期：2026-09-06。第三批已实现并完成针对性回归，修改保留在当前工作区，未提交 Git。第一、二批的改动保留。

本批沿用原有 TaskManager、子代理循环、检查点与审批桥接，没有拆分框架或改变任务存储格式。

## 修复了什么，为什么有用

| 场景 | 原来的实际缺口 | 现在的行为 | 价值与代价 |
|---|---|---|---|
| 停止后台任务 | 管理器只设置取消标记；执行器正在等待模型、审批或命令时，不一定及时检查标记 | 管理器中断执行协程，等待清理和状态落盘，再返回停止结果；初始化期间的资源也会清理 | 避免界面操作结束后任务继续执行。清理期间可能短暂等待 |
| 给子代理发送立即打断 | interrupt 只是随输入入队，没有真正中断正在生成的模型请求 | 中断模型生成或审批等待；正在执行的工具先收尾并记录结果，跳过本轮后续工具，再读取新要求 | 纠正方向真正生效，同时保留已执行结果。正在执行的慢工具仍会延迟新要求生效 |
| 恢复旧任务 | 恢复分支直接入队，绕过创建分支的嵌套检查，也没有对比旧任务与当前会话权限 | 同等权限直接恢复；权限更高或目录越界时，模型工具拒绝自动恢复，任务面板展示差异供用户确认 | 防止普通会话悄悄恢复高权限任务。跨权限恢复多一次明确确认 |
| 执行旧任务 | 执行器没有完整使用任务保存的 shell / mode 标志，还会混入全局审批设置 | 按保存的工作目录、模式、终端能力、自动审批和目录信任运行 | 避免检查与执行不一致。以前依赖“记录禁止但实际上可以执行”的旧任务会受到限制 |

## 具体使用变化

### 停止后台任务

- 排队中的任务仍可直接取消。
- 运行中的任务会等执行清理完成才标记为 canceled。测试覆盖审批等待、初始化等待及真实前台 Shell 子进程。
- 等待清理时不持有队列锁，其他任务仍能正常调度。
- 单个任务被取消后，工作槽仍可继续执行后续任务。
- 已完成的写入、外部请求不会撤销。显式启动的独立后台进程仍有自己的生命周期，可通过其进程 ID 停止；本次前台 Shell 验证针对其进程组，不承诺杀死自行脱离进程组的程序。

### 打断子代理

- 普通补充输入保持第二批之前约定的“下一轮生效”。
- interrupt=true：正在生成的回复会停止；未完整完成的生成内容不作为已完成回复带入下一轮。
- 如果正在等待审批，取消该次等待并清除待审批记录，不执行该工具。
- 如果工具已经开始执行，等待它返回，保留结果；本轮还未执行的工具逐个记录“未执行”，防止恢复后的模型误以为它们已经完成。
- 这不是撤销工具操作，也不是紧急杀进程。需要终止执行时应使用停止功能。

### 恢复任务与权限确认

比较范围包括：工作目录、规划/执行模式、是否允许运行终端命令、是否允许目录外访问、是否自动批准操作。合法子目录不视为目录越界。

- 模型调用恢复工具时，没有可自行填写的提权确认参数；旧任务权限超出当前会话时，应由用户从任务面板操作。
- 面板展示原工作目录和权限差异；用户取消时不入队。
- 确认绑定具体任务、原权限及本次比较上下文。确认期间权限变化时，原确认失效，需要重新查看。
- 入队时在管理器锁内再次核对任务权限，防止核对后任务范围改变。
- 保持原任务 ID、目录、来源与保存的权限，不把旧任务迁到当前聊天目录，不偷偷降低原任务权限。
- 没有选中会话时按普通运行环境比较，不依赖来源会话必须存在；旧的独立任务仍可在来源会话删除后接受审查并恢复。
- 内部已授权的管理器调用仍可恢复同一任务。模型入口同时补齐禁止任务嵌套的检查。

执行器本次还保留已有 feature 配置，避免重新构造默认 feature 时覆盖执行策略开关。自动审批与目录信任按任务中各自保存的标志使用；这里只修正后台任务执行，不重定义全局 auto 语义。

## 兼容边界

1. 旧任务如果保存了 allow_shell=false 或 mode=plan，现在会实际遵守。用户确认恢复只确认原有权限，不把这些限制改成允许。
2. HTTP 恢复接口对同等权限仍返回原来的任务记录；需要确认时返回 `resume_confirmation_required` 和具体差异。工作台已支持该流程；自写调用方需处理此响应，再提交确认标识。
3. 恢复仍从已保存的完整检查点继续，不是任意命令的断点续跑。被停止的命令可能已经产生部分副作用，本批没有增加事务回滚，也不保证外部操作只执行一次。
4. OS 读取白名单、全面 Shell 解析、历史清理、大型管理器重构仍未实施。
