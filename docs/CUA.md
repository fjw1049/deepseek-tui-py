# LCU 桌面工具接入

Workbench 通过 LCU 官方共享客户端连接本机 CUA runtime，向模型提供 `cua_js` 和
`cua_js_reset`。工具参数、描述和运行时说明来自实际连接，不维护另一套桌面 API。
现有 `browser_use` 继续独立工作。

## 插件页管理

“插件 → 已安装”中内置“电脑控制”卡片，支持启用、停用和刷新组件状态。
卡片使用现有 CUA 设置及授权流程，不通过第三方插件信任开关授予桌面权限。
“已安装”指应用内置的适配器；组件是否完整单独显示，模型兼容性和应用授权在使用时检查。
状态接口 `/v1/cua/status` 只检查本地文件，不连接运行时或触发桌面访问。
macOS 上卡片详情列出“始终允许的应用”（`/v1/cua/apps`，读取 `lcu apps list --json`），
可逐个撤销（`/v1/cua/apps/revoke`）。撤销只接受刚列出的 bundle id，由 LCU 要求
Touch ID 或登录密码；不提供“始终允许”入口，长期授权仍只能在授权卡片上由用户选择。
设置页“自动允许控制所有应用”（`[cua] auto_allow_apps = true`）开启后，原生应用请求由宿主
按“本次会话”自动批准，不弹授权卡片，无人值守任务同样生效；不写入“始终允许”名单，
关闭后重启即恢复询问。Workbench 与终端自身仍禁止控制，Chrome 站点授权仍逐个询问。
本版本不提供自动下载或安装 LCU。

## 安装和开启

1. 从 [LCU releases](https://github.com/amontlabs/lcu/releases) 下载适合系统的发布包，
   校验发布的 SHA256，解压后运行 `./scripts/install.sh --runtime-only`。
   本次验证使用 v0.11.6。macOS 使用 Apple Silicon 和本机 ChatGPT runtime；
   Linux 需要上游支持的 X11 环境。此适配器不支持 Windows。
2. 启动 Workbench：程序会自动检测已安装的桌面控制组件，并在未明确设置开关时启用。
   用户曾在设置或用户配置中明确关闭时会保持关闭；需要使用时再开启。
3. 按系统提示授予辅助功能、屏幕录制权限；具体应用或网站权限仍由运行时请求，
   在聊天中的授权卡片上选择。未知授权表单默认取消。

也可以在用户级配置中设置：

```toml
[cua]
enabled = true
installation = "~/.local/share/lcu/current"
chrome = false
```

项目级配置不能开启 CUA 或替换其可执行程序路径。Workbench 启动后端前会检测
安装目录、Node 路径和共享客户端，完整安装且未明确设置开关时自动写入启用配置。
不自动下载运行时，不代替用户授予应用或系统权限。独立 Python 入口仍默认关闭。
LCU 的许可、运行时依赖和平台要求以上游发布说明为准。

设置页中的“继承配置文件”表示尚未在界面指定覆盖值，不表示关闭。
可以直接选择“关闭”写入明确的禁用配置。主模型已知不支持图片时，必须先配置
`vision.model` 为支持视觉的模型；否则不启动 CUA，也不向模型提供桌面工具。
DeepSeek-V4.1-Flash 的 API 名称是 `deepseek-flash`，官方文档确认支持图片；把它设为主模型时
截图直接交给主模型，也可以只设 `vision.model = "deepseek::deepseek-flash"` 作为视觉辅助。
旧名 `deepseek-v4-flash` 仍按“未确认支持图片”处理。
未知模型能力仍按现有图片管线尝试，不代表已通过视觉验证。

## 可选 Chrome

已有官方 ChatGPT 浏览器扩展时，运行：

```sh
~/.local/share/lcu/current/bin/lcu browser install
~/.local/share/lcu/current/bin/lcu browser status
```

随后关闭再开启扩展，或自行重启浏览器，让原生宿主重新连接；再在 CUA 设置中开启
Chrome 并新建对话。注册会影响同一桌面账号的原生宿主配置，应先备份原有
`com.openai.codexextension.json`。不需要关闭用户标签页来安装注册。
仅注册成功不代表现有浏览器连接已切换，也不代表网站授权已经授予。

## 通用架构和约束

```text
Engine / 子任务
  → ToolSpec（cua_js / cua_js_reset / cua_observe）
  → Python 会话、授权桥、桌面锁、图片管线
  → Node JSONL bridge
  → LCU createCuaClient
  → 本机 CUA runtime
```

- 每个会话有独立 REPL；主任务和子任务都传递实际会话、轮次、调用 ID。
  每次取得桌面后建立独立的运行段 ID，并在元数据中保留宿主轮次 ID。
  原生运行时会记住已结束的 ID，因此接管恢复和子任务交接不能复用旧运行段。
  轮次结束通知由宿主发送，模型不能自行伪造生命周期通知。
- 进程内第一次连接在回合开始时完成，并缓存运行时返回的工具目录和说明。之后的对话和
  子任务直接用缓存注册工具，第一次真正调用 `cua_js` 时才连接，所以不碰桌面的对话和
  子任务不会启动 LCU。连接后若运行时说明有变化，会附在该次结果里交给模型。
  Workbench 轮询的上下文用量统计从不连接 CUA，也不等待进行中的 CUA 调用。
- 同一账号的本适配器通过文件锁串行使用桌面，锁覆盖观察、操作和结果验证的完整轮次。
  等锁最多 30 秒，超时返回"桌面正被其他任务使用"，不执行任何操作，也不断开连接；
  这避免了父任务等待后台子任务时双方互等。
  它不阻止用户或其他桌面控制软件操作电脑。父任务委派子任务前释放并关闭自己的连接。
- 停止当前任务会中断调用、释放桌面锁并丢弃 REPL。人工接管同样先停止原生输入，
  但保留桌面锁给用户，直到用户继续或停止任务；其他使用本适配器的会话不能抢占。
  监听覆盖连接初始化和两次工具调用之间的空档。恢复时会提示旧变量已失效；
  `cua_observe` 仍可查看界面，实际操作持续拦截，直到重新查看成功；查看其他目标视为切换到该目标，
  原目标退出或崩溃时不会一直卡住。
  这不是所有会话的全局急停按钮，也不能撤回已经发生的外部动作。
- 应用和网站授权保持运行时范围；子任务只转发单次允许。
  普通工具自动批准不替代应用授权。当前 Workbench 应用的授权请求会被拒绝。
- 运行时文档不做静默头尾截断。单次文本超过 64 KiB 时完整落盘，返回明确的
  超限提示和读取路径，不把半份文档当作完整文档交给模型，也不重放已执行的动作。
  上下文压缩或历史工具内容裁剪后，会显式提醒模型重新获取 API 文档。
  每次新连接（含人工协助后的重连）运行时都会再发一遍首调指南；如果之前那份仍在上下文里，
  新结果中的这段文本替换为指向原调用的一行说明，模型主动调用 `rewriteDocumentation()` 时保持完整。
  模型调用不存在的 API（`… is not a function`）时，错误结果附带回到文档的提示。
- 截图沿用现有图片存储与模型输入管线，保留像素尺寸（大小合适时也保留原始字节），并记录调用来源。
  像素坐标与应用逻辑坐标仍须按运行时文档转换；文字视觉辅助的精度不能等同于原生视觉模型。
  图片的 `codex/imageDetail` 会保留在内部记录中。OpenAI 兼容接口默认将
  `original` 显式降为 `high` 以兼容旧端点；确认该提供方和当前模型支持后，可在对应
  `[providers.<名称>]` 下设置 `image_detail_original = true` 透传 `original`。
  Anthropic 图片协议不传该参数。
- 断连、超时和更新不会盲目重放点击、提交等可能已经执行的操作。
  遇到结果不确定时，重新连接并观察后再决定下一步。桥接进程在两次调用之间退出时，
  若模型代码已在旧连接中运行，下一次调用会先提示旧变量失效而不执行；否则直接重连。
  只有模型代码真正运行过，停止、接管或断连后才会出现这条提示。
  初始化失败后有 30 秒重试间隔，同一进程内的所有对话和子任务共享，避免反复等待
  不可用的桌面运行时；失败同时作废缓存的工具目录，下一回合会如实提示不可用。
  用户停止或接管不触发该退避。
- 截图不缩放，原始字节在 3.75 MiB 以内原样发送；更大的截图按原像素尺寸重新编码，
  逐级降低 JPEG 质量并检查实际字节数，以满足提供方单图 5 MiB 的限制，坐标空间不变。
  最低质量仍超限则明确报错，请求更小的观察，不重放前一次操作。

## 与整个系统的协作

提示词分三层，各管一件事，避免重复和冲突：

| 层 | 来源 | 内容 |
|---|---|---|
| 运行时 | LCU 下发（工具描述、初始化说明、首次调用返回的指南） | API、操作流程、确认分级策略；原样转发，不在仓库保存副本 |
| 宿主桌面规则 | `src/deepseek_tui/prompts/computer_use.md` | 只写运行时不知道的事：工具改名、与 `browser_use` 分工、释放与重新观察、人工协助、结束契约、子任务，以及与具体应用无关的操作原则 |
| 跨界面路由 | `src/deepseek_tui/prompts/surfaces.md` + `src/deepseek_tui/surfaces.py` | 按当前可用界面生成的分层与通用原则 |

- 界面注册表 `surfaces.py` 是路由列表、各界面指南（`browser.md`、`computer_use.md`）、
  任务交付与工具聚焦、观察无进展检测和视觉辅助上下文的唯一来源。新增界面只需加一项和它的指南。
- 任务交付：操作界面后必须通过 `finish_task` 校验结果，`completed` 需要证据和空的剩余事项，
  否则用 `partial`/`blocked`。`browser_skill` 按 action 分类：`run_site`、`capture_start`、
  `capture_stop` 纳入契约，读取和编写技能不纳入。中途停止或未验证的回放不能作为完成证据。
  CUA 完成证据必须包含最新的 `cua_observe` 结果（执行过代码时须在最后一次执行之后）。执行过 `cua_js`
  的任务还需通过 `verification` 将结论、引用和局限关联起来（不要求逐字出现在答复里）；只查看未操作的任务不需要。代码成功、打印文字和
  重置连接都不产生完成证据。再次查看会替换旧观察证据；查看失败或预期文字未出现时，
  不能沿用旧成功结果。原生应用按运行时 app id 核对；浏览器运行时只提供界面类别，
  目前不能据此强制核对上次操作的 tab id，仍需模型核对观察目标和内容。
  `expect` 检查可见文字片段，不能验证业务语义；这些校验也不能自动证明结论解释正确。
  不确定的操作记录不会因查看或重置消失，仍需用户在操作面板确认后重新查看。
  主代理直接停下会被拦一次，再停下按未核验的 partial 结束；子代理先提交 `finish_task`，
  再输出摘要或原有 schema 的结构化结果，任务状态随子代理结果单独保存并传给父代理。
  受限配置没有 `finish_task` 时主代理不启用此契约。工具聚焦仍只用于主代理的浏览器界面。
- 观察无进展：主代理与子代理共用检查。CUA 比较宿主完整观察，忽略文字中的元素编号和焦点提示，
  保留最近 8 份观察识别来回循环；模型打印的摘要不能重置计数。`expect` 未满足时，
  其他文字或截图变化也不能清除计数。连续 3 次无进展提醒，8 次暂停继续执行代码；
  长时间只执行代码而不通过 `cua_observe` 查看也会暂停。查看和重置仍可用，
  新观察出现变化、用户接管或报告 `partial`/`blocked` 都是恢复或结束路径。
  截图变化保守地视为变化以支持画布；像素变化本身不能证明任务进展，文字结果应使用 `expect`。
  其他界面继续沿用相邻观察比较。
  截图读取与比较在线程中执行；新回合、用户插话、用户交接后重新计数。
- 路由原则与运行时一致：操作 GUI 应用走界面工具，不用 `osascript`、JXA、System Events，
  除非用户点名该方法；用户点名的应用或方法优先。确认规则以各界面自己的策略为准，跨界面取更严格的；
  发送、删除、购买、分享等效果无论用哪个工具（包括 shell 脚本）都需要同样的确认。
- 跨界面：浏览器任务阶段允许 `cua_js` / `cua_js_reset` / `cua_observe`，网页到桌面应用的任务不必额外申请工具。
- 模型请求失败：401/402/403 等客户端错误不再重试（408、429、5xx 仍重试），402 提示余额或额度不足；
  界面任务因此中断时以 blocked 结束并列出原因。
- 人工协助：`request_user_input(kind="action", surface="desktop", reason=...)` 先结束 CUA 轮次、
  释放桌面锁并丢弃 REPL，再用提问卡片请用户在电脑上完成一步；返回结果要求模型重新观察，
  用户的“已完成”只是陈述，不等于已验证。普通提问也会释放桌面锁、丢弃 REPL，并通知模型重新初始化与观察。
  授权请求被取消时会发送结束事件，前端不保留待处理卡片；权限卡完整展示范围且仅接受明确选项。
  子任务没有提问工具，指南要求它停止桌面操作并报告阻碍。
- 无人值守：后台任务和自动化运行中，应用授权请求直接取消（只有“始终允许”的应用可用），
  桌面协助请求直接报错，提示模型说明需要人工的步骤，不会挂起到超时。
- 界面：工具卡片显示“电脑控制”和调用的 `title`，轮次状态显示“正在操作电脑”。
- 窗口预览：运行时在每次结果的 `_meta["codex/toolSurface"]` 中给出刚操作的应用（bundle id），
  宿主保存为工具项的 `cua_surface`。操作栏下方的预览卡片仅在该应用有唯一普通窗口时实时显示：
  用户展开后，macOS 上实时捕获这一个窗口（最大 960 px、15 fps，需要为 Workbench 开启“屏幕录制”）；
  无法实时捕获（Linux、未授权、浏览器标签页）时显示该调用自己的截图
  （`/v1/cua/frames/{item}/{asset}`，只提供该工具项记录的 CUA 截图）。从不退化为整个桌面。
  预览只供用户查看，不进入模型上下文；默认显示缩略图与当前动作，点击展开，X 或 Escape 收起。
  收起停止实时采集但不停止任务、不改变控制权；轮次结束保留当前展开状态与最后画面，下一轮默认紧凑。子代理的桌面步骤经 mailbox 的 `cua_surface` 驱动父对话的实时预览（不带截图）。
  设置页“显示操作窗口预览”可关闭，从下一次任务起生效。
  ChatGPT 自带的 PiP 只接受由 ChatGPT 启动的原生 helper，无法复用，因此由宿主自行实现。
  辅助视觉模型分析截图时会收到最近一次界面操作（`cua_js` 的 `title`、`code`）作为上下文。
- 评测：`evals/suites/surface_routing` 是真实模型的单步路由探针，只观察工具选择，
  不执行工具、不触碰桌面；本机装有 LCU 时使用运行时真实工具目录（证据中记录
  `cua_catalog=runtime`），否则使用占位描述。用例标注 `tuned`（调提示词时见过）和
  `held-out`（之后新写、未用于调参），后者用来检查泛化。

移植到其他 Agent 系统时，只需替换 ToolSpec、授权 UI、图片输入和轮次回调这四个宿主边界；
保持 LCU 共享客户端及其原始工具契约。不要让模型直接调用内部生命周期接口。

## 验证记录与边界

2026-10-20 在本机使用 LCU v0.11.6、ChatGPT 26.1013.40934、
CUA 0.0.30 验证了连接、动态工具目录、真实 TextEdit 截图（1312×844）、
中文输入及保存后的文件内容。测试只操作专门创建的临时文件，应用权限为本次允许。
这属于真实运行时的脚本集成测试，尚不等于模型自主完成业务任务的端到端验证。
Linux 和 Chrome 页面操作未在本次验证中覆盖。

自动化测试覆盖桥接协议、权限范围、等待授权时取消、桌面锁竞争、
连接崩溃不重放、停止后清理、工具目录、配置隔离及截图尺寸。

同日复审补充了三个先失败再修复的回归用例：授权等待不阻止清理请求超时、
空闲桥接进程退出后可以重新连接、LCU 安装不可用不导致普通子任务启动失败。
额外验证了正常操作仍可等待人工授权。Python wheel 已实际构建，并核对包含完整
CUA 模块和 `bridge.mjs`。前端生产构建通过不代表已完成安装包的安装验收；
实际启动的 Python 后端必须包含本次代码。

同日优化后的最终验收：

- Python 全量非 live 测试：3553 通过、127 跳过、36 未选择、3 失败。
  三项失败分别是 `test_consumer_hint_names_the_ledger_and_gives_a_tiebreaker`、
  `test_end_of_turn_self_check_clause_present`、
  `test_long_session_reminder_covers_core_disciplines`。在未修改的 Git HEAD
  导出副本中单独运行这三项，均出现相同失败，属于已有提示词文案断言问题。

  需要监听回环端口的测试在允许本机端口访问的环境中执行。
- CUA 专项覆盖增加了初始化时停止、空闲时接管、交接后重新获取运行段、

## 控制面板与验收（2026-10-25）

紧凑入口显示缩略图、当前动作，以及独立挂载的“我来操作 / 继续任务”和“停止”按钮。
正常执行时省略重复的“AI 正在操作”；等待、交接、断连和人工协助状态仍直接显示。
接管请求发出后先显示交接中，后端确认原生连接关闭且桌面锁已保留后，才显示由你操作。
X 只收起查看器，不卸载控制栏、不归还控制权；点击紧凑入口重新展开。关闭预览设置仍保留控制入口。
画面采集故障只在展开查看器内解释；控制连接异常和需要用户处理的原因在紧凑入口也可见。
结束后的静态画面明确显示“最后画面”，停止、失败和结束分别呈现，不代表任务目标已验证成功。

应用窗口预览按应用标识匹配。当前运行时没有提供精确的被操作窗口标识，因此多个普通窗口时不再猜选最前窗口：停止实时采集，改用任务返回的截图，并显示原因。浏览器始终使用工具调用截图，不要求 Workbench 录屏权限。
收起后的缩略图继续接收任务截图；无法匹配目标时，不把之前的实时窗口冒充当前目标。

调用前写入最小回执，异常中断后保留结果未知状态，不自动重放可能已经发生的操作。
回执只包含轮次、调用 ID、结果和时间，保存在用户数据目录的 `state/cua` 下，不保存代码或截图。
重新创建同一会话时读取未完成回执；只有用户明确核对后才允许继续。
前端刷新可恢复后端仍驻留的活动会话状态；尚未加载的历史会话不属于后台实时控制面板。
状态接口返回的“已配置”不表示系统权限已经验证，权限仍在实际使用时检查。
关闭自动授权不会撤回运行时已授予的会话权限，应停止任务并重启运行时；长期授权另行撤销。

建议重启 Workbench（包含 Python 后端）后按以下顺序验收：

1. 发起简单桌面任务，观察预览、运行状态和控制按钮；收起查看器后点击紧凑入口重新展开。任务结束后紧凑入口出现 X 可关闭卡片；仍有待核对的结果时不提供关闭。后续未调用电脑控制的轮次不显示卡片，也不能从面板接管。
2. 点击“我来操作”：先出现交接中，完成后手动操作，再点击“继续任务”，确认助手重新观察。
3. 接管期间在另一个会话发起桌面任务，确认其等待或报告桌面占用，不抢占输入。
4. 触发需要登录等人工步骤，完成后从控制面板继续，确认原任务恢复，无需发送新消息。
5. 在调用进行中停止或模拟连接断开，确认显示停止或结果待核对，不显示成功、不重复操作。
6. 切换被操作的应用，确认旧应用截图不会作为新目标画面；撤掉录屏权限时确认错误可见。
7. 浏览器局部操作报错后，确认“我来操作”入口仍在；真实连接异常时输入不可用。

自动化覆盖控制交接、跨会话锁、过期轮次/版本拒绝、未知结果回执、子任务回执聚合、
人工协助恢复、预览状态与前端控制按钮。真实系统授权弹窗、多窗口截图匹配、实际桌面输入

### 系统权限引导

macOS 用户展开活动任务的查看器时检查 Workbench 的预览录屏权限；未授权时，针对同一应用的同一次权限缺失只主动显示一次引导，跨任务和重新打开应用
保留已提醒记录；后台确认已授权后清除记录，之后再次失效才重新提醒。
记录只用于避免打扰，绝不作为授权依据。弹窗显示系统里的实际应用名称（开发版通常为 Electron），
点击“去开启”直接打开屏幕录制设置；运行组件报告的辅助功能和录屏权限也在同一窗口
列出，可分别跳转。插件详情提供相同入口。

查看器展开时返回应用会重新检查 Workbench 录屏权限，检测已授权后刷新预览；运行组件的授权状态
以系统设置为准，不把打开设置页当成授权成功。若系统要求重启，先停止任务再重开应用。
升级旧窗口后也需重启一次加载新增 IPC，旧窗口会显示明确提示，不抛出渲染错误。


权限引导复审补充：弹窗逐项说明“允许显示操作画面”“允许 AI 读取界面”
和“允许点击和输入”，并展示授权应用名称；名称未查到前不猜测 Workbench。
首次点击录屏授权入口会先向 macOS 发起录屏请求，再打开设置页，避免列表中没有应用。
引导挂在会话层，切换操作目标不再关闭弹窗；重新检查同时重试组件权限列表。
自动授权检测仅覆盖当前 Workbench 的录屏权限。组件辅助功能和录屏状态以系统开关

### 授权层次

系统权限（录屏、辅助功能）通常一次开启即可复用；不会按任务重复申请。
运行组件权限状态无法直接验证时，仅提供“查看系统设置”，不显示未经验证的
“未授权”或“已授权”。当前应用的录屏权限从系统实时读取，已授权时无需再次操作。

聊天里的应用/网站访问确认是独立的运行时授权，保留原生提供的允许一次、
本次运行会话和始终允许范围；不会因为用户开启系统权限而自动提升为永久允许。
用户关闭引导后自行去系统设置，返回当前活动任务时也会重新检测并刷新预览。
授权刷新只重试画面采集，不重放点击、输入或提交，不自动解除用户接管暂停。

## 观察与交付优化（2026-10-27）

- `cua_observe` 每个 REPL 只绑定一次目标，之后只取一次完整状态，不再把同一棵无障碍树输出两遍；
  Linux/Windows 可用 `window_id` 观察窗口（这两个平台的 `getApp` 只接受窗口）。
- `expect` 比较前统一全半角、引号、大小写和多余空白，不改变字符本身。
- 宿主在 REPL 中包装运行时返回的目标，记录每次调用实际发出的界面输入。坐标点击提示按实际动作判断；
  失败调用若未发出任何输入（或唯一输入在发送前被运行时拒绝），不再强制先观察。未取得记录时沿用旧规则。
- 运行时错误按代码和固定文案命名（失效元素、按键名、应用 ID、平台不支持的调用形式、锁屏、
  用户停止或干预、拒绝访问、版本不符），附对应处理；不再附加 MCP 通用的“不要猜参数名”提示。
- 收尾阶段：用过电脑控制时保留只读的 `cua_observe`、给两轮、超时 180 秒，缺证据时提示观察。
  此前收尾只开放 `finish_task`，而完成又要求新观察，导致正确结果被判为未核验。

真实验证（LCU 0.11.6、TextEdit、`deepseek-v4-pro`，脚本与数据见 `scratch/cua-bench-2026-10-27/`）：
稳态观察输出 2091→1045 字节；`expect` 格式变体命中 1/5→5/5，反例误报仍 0/4；
