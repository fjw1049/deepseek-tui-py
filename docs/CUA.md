# LCU 桌面工具接入

Workbench 通过 LCU 官方共享客户端连接本机 CUA runtime，向模型提供 `cua_js` 和
`cua_js_reset`。工具参数、描述和运行时说明来自实际连接，不维护另一套桌面 API。
现有 `browser_use` 继续独立工作。

## 插件页管理

“插件 → 已安装”中内置“电脑控制”卡片，支持启用、停用和刷新组件状态。
卡片使用现有 CUA 设置及授权流程，不通过第三方插件信任开关授予桌面权限。
“已安装”指应用内置的适配器；组件是否完整单独显示，模型兼容性和应用授权在使用时检查。
状态接口 `/v1/cua/status` 只检查本地文件，不连接运行时或触发桌面访问。
macOS 上卡片详情列出“始终允许的应用”（`/v1/cua/apps`，读取 `lcu apps list --json`），
可逐个撤销（`/v1/cua/apps/revoke`）。撤销只接受刚列出的 bundle id，由 LCU 要求
Touch ID 或登录密码；不提供“始终允许”入口，长期授权仍只能在授权卡片上由用户选择。
本版本不提供自动下载或安装 LCU。

## 安装和开启

1. 从 [LCU releases](https://github.com/amontlabs/lcu/releases) 下载适合系统的发布包，
   校验发布的 SHA256，解压后运行 `./scripts/install.sh --runtime-only`。
   本次验证使用 v0.11.6。macOS 使用 Apple Silicon 和本机 ChatGPT runtime；
   Linux 需要上游支持的 X11 环境。此适配器不支持 Windows。
2. 启动 Workbench：程序会自动检测已安装的桌面控制组件，并在未明确设置开关时启用。
   用户曾在设置或用户配置中明确关闭时会保持关闭；需要使用时再开启。
3. 按系统提示授予辅助功能、屏幕录制权限；具体应用或网站权限仍由运行时请求，
   在聊天中的授权卡片上选择。未知授权表单默认取消。

也可以在用户级配置中设置：

```toml
[cua]
enabled = true
installation = "~/.local/share/lcu/current"
chrome = false
```

项目级配置不能开启 CUA 或替换其可执行程序路径。Workbench 启动后端前会检测
安装目录、Node 路径和共享客户端，完整安装且未明确设置开关时自动写入启用配置。
不自动下载运行时，不代替用户授予应用或系统权限。独立 Python 入口仍默认关闭。
LCU 的许可、运行时依赖和平台要求以上游发布说明为准。

设置页中的“继承配置文件”表示尚未在界面指定覆盖值，不表示关闭。
可以直接选择“关闭”写入明确的禁用配置。主模型已知不支持图片时，必须先配置
`vision.model` 为支持视觉的模型；否则不启动 CUA，也不向模型提供桌面工具。
DeepSeek-V4.1-Flash 的 API 名称是 `deepseek-flash`，官方文档确认支持图片；把它设为主模型时
截图直接交给主模型，也可以只设 `vision.model = "deepseek::deepseek-flash"` 作为视觉辅助。
旧名 `deepseek-v4-flash` 仍按“未确认支持图片”处理。
未知模型能力仍按现有图片管线尝试，不代表已通过视觉验证。

## 可选 Chrome

已有官方 ChatGPT 浏览器扩展时，运行：

```sh
~/.local/share/lcu/current/bin/lcu browser install
~/.local/share/lcu/current/bin/lcu browser status
```

随后关闭再开启扩展，或自行重启浏览器，让原生宿主重新连接；再在 CUA 设置中开启
Chrome 并新建对话。注册会影响同一桌面账号的原生宿主配置，应先备份原有
`com.openai.codexextension.json`。不需要关闭用户标签页来安装注册。
仅注册成功不代表现有浏览器连接已切换，也不代表网站授权已经授予。

## 通用架构和约束

```text
Engine / 子任务
  → ToolSpec（cua_js / cua_js_reset）
  → Python 会话、授权桥、桌面锁、图片管线
  → Node JSONL bridge
  → LCU createCuaClient
  → 本机 CUA runtime
```

- 每个会话有独立 REPL；主任务和子任务都传递实际会话、轮次、调用 ID。
  每次取得桌面后建立独立的运行段 ID，并在元数据中保留宿主轮次 ID。
  原生运行时会记住已结束的 ID，因此接管恢复和子任务交接不能复用旧运行段。
  轮次结束通知由宿主发送，模型不能自行伪造生命周期通知。
- 进程内第一次连接在回合开始时完成，并缓存运行时返回的工具目录和说明。之后的对话和
  子任务直接用缓存注册工具，第一次真正调用 `cua_js` 时才连接，所以不碰桌面的对话和
  子任务不会启动 LCU。连接后若运行时说明有变化，会附在该次结果里交给模型。
  Workbench 轮询的上下文用量统计从不连接 CUA，也不等待进行中的 CUA 调用。
- 同一账号的本适配器通过文件锁串行使用桌面，锁覆盖观察、操作和结果验证的完整轮次。
  等锁最多 30 秒，超时返回"桌面正被其他任务使用"，不执行任何操作，也不断开连接；
  这避免了父任务等待后台子任务时双方互等。
  它不阻止用户或其他桌面控制软件操作电脑。父任务委派子任务前释放并关闭自己的连接。
- 停止当前任务或接管暂停会中断调用、释放桌面锁并丢弃 REPL；恢复后应重新观察。
  监听覆盖连接初始化和两次工具调用之间的空档。恢复时会提示旧变量已失效。
  这不是所有会话的全局急停按钮，也不能撤回已经发生的外部动作。
- 应用和网站授权保持运行时范围；子任务只转发单次允许。
  普通工具自动批准不替代应用授权。当前 Workbench 应用的授权请求会被拒绝。
- 运行时文档不做静默头尾截断。单次文本超过 64 KiB 时完整落盘，返回明确的
  超限提示和读取路径，不把半份文档当作完整文档交给模型，也不重放已执行的动作。
  上下文压缩或历史工具内容裁剪后，会显式提醒模型重新获取 API 文档。
  每次新连接（含人工协助后的重连）运行时都会再发一遍首调指南；如果之前那份仍在上下文里，
  新结果中的这段文本替换为指向原调用的一行说明，模型主动调用 `rewriteDocumentation()` 时保持完整。
  模型调用不存在的 API（`… is not a function`）时，错误结果附带回到文档的提示。
- 截图沿用现有图片存储与模型输入管线，保留像素尺寸（大小合适时也保留原始字节），并记录调用来源。
  像素坐标与应用逻辑坐标仍须按运行时文档转换；文字视觉辅助的精度不能等同于原生视觉模型。
  图片的 `codex/imageDetail` 会保留在内部记录中。OpenAI 兼容接口默认将
  `original` 显式降为 `high` 以兼容旧端点；确认该提供方和当前模型支持后，可在对应
  `[providers.<名称>]` 下设置 `image_detail_original = true` 透传 `original`。
  Anthropic 图片协议不传该参数。
- 断连、超时和更新不会盲目重放点击、提交等可能已经执行的操作。
  遇到结果不确定时，重新连接并观察后再决定下一步。桥接进程在两次调用之间退出时，
  若模型代码已在旧连接中运行，下一次调用会先提示旧变量失效而不执行；否则直接重连。
  只有模型代码真正运行过，停止、接管或断连后才会出现这条提示。
  初始化失败后有 30 秒重试间隔，同一进程内的所有对话和子任务共享，避免反复等待
  不可用的桌面运行时；失败同时作废缓存的工具目录，下一回合会如实提示不可用。
  用户停止或接管不触发该退避。
- 截图不缩放，原始字节在 3.75 MiB 以内原样发送；更大的截图按原像素尺寸重新编码，
  以满足提供方单图 5 MiB 的限制，坐标空间不变。

## 与整个系统的协作

提示词分三层，各管一件事，避免重复和冲突：

| 层 | 来源 | 内容 |
|---|---|---|
| 运行时 | LCU 下发（工具描述、初始化说明、首次调用返回的指南） | API、操作流程、确认分级策略；原样转发，不在仓库保存副本 |
| 宿主桌面规则 | `src/deepseek_tui/prompts/computer_use.md` | 只写运行时不知道的事：工具改名、与 `browser_use` 分工、释放与重新观察、人工协助、结束契约、子任务，以及与具体应用无关的操作原则 |
| 跨界面路由 | `src/deepseek_tui/prompts/surfaces.md` + `src/deepseek_tui/surfaces.py` | 按当前可用界面生成的分层与通用原则 |

- 界面注册表 `surfaces.py` 是路由列表、各界面指南（`browser.md`、`computer_use.md`）、
  任务交付与工具聚焦、观察无进展检测和视觉辅助上下文的唯一来源。新增界面只需加一项和它的指南。
- 任务交付：调用任一界面的操作工具（`browser_use`、`cua_js`、`cua_js_reset`；`browser_skill`
  不算）后，本轮必须以 `finish_task` 结束：`completed` 需要引用成功结果作为证据，否则用
  `partial`/`blocked` 列出剩余事项；直接停下会被拦一次，再停下按未核验的 partial 结束。
  工具目录里没有 `finish_task`（子任务、受限配置）时不启用。工具聚焦（阶段内禁用其他工具）
  只对 `focus=True` 的界面生效，目前只有浏览器；桌面操作常是编码任务中的一步，不能锁住工具。
- 观察无进展：每次界面结果都与本回合已见过的观察比较（截图按灰度缩略图的最大块差，
  文本按原文）。有截图时只看截图，纯文本结果单独计数。连续 3 次没有新内容时提醒模型换方法、
  请求协助或报告阻碍；连续 8 次后拒绝继续执行该界面的工具。新回合和用户交接后重新计数。
- 路由原则与运行时一致：操作 GUI 应用走界面工具，不用 `osascript`、JXA、System Events，
  除非用户点名该方法；用户点名的应用或方法优先。确认规则以各界面自己的策略为准，跨界面取更严格的；
  发送、删除、购买、分享等效果无论用哪个工具（包括 shell 脚本）都需要同样的确认。
- 跨界面：浏览器任务阶段允许 `cua_js` / `cua_js_reset`，网页到桌面应用的任务不必额外申请工具。
- 模型请求失败：401/402/403 等客户端错误不再重试（408、429、5xx 仍重试），402 提示余额或额度不足；
  界面任务因此中断时以 blocked 结束并列出原因。
- 人工协助：`request_user_input(kind="action", surface="desktop", reason=...)` 先结束 CUA 轮次、
  释放桌面锁并丢弃 REPL，再用提问卡片请用户在电脑上完成一步；返回结果要求模型重新观察，
  用户的“已完成”只是陈述，不等于已验证。等待任何用户回答前都会先释放桌面锁。
  子任务没有提问工具，指南要求它停止桌面操作并报告阻碍。
- 无人值守：后台任务和自动化运行中，应用授权请求直接取消（只有“始终允许”的应用可用），
  桌面协助请求直接报错，提示模型说明需要人工的步骤，不会挂起到超时。
- 界面：工具卡片显示“电脑控制”和调用的 `title`，轮次状态显示“正在操作电脑”。
  辅助视觉模型分析截图时会收到最近一次界面操作（`cua_js` 的 `title`、`code`）作为上下文。
- 评测：`evals/suites/surface_routing` 是真实模型的单步路由探针，只观察工具选择，
  不执行工具、不触碰桌面；本机装有 LCU 时使用运行时真实工具目录（证据中记录
  `cua_catalog=runtime`），否则使用占位描述。用例标注 `tuned`（调提示词时见过）和
  `held-out`（之后新写、未用于调参），后者用来检查泛化。

移植到其他 Agent 系统时，只需替换 ToolSpec、授权 UI、图片输入和轮次回调这四个宿主边界；
保持 LCU 共享客户端及其原始工具契约。不要让模型直接调用内部生命周期接口。

## 排错和回退

- 工具未出现：检查用户配置开关、是否为计划模式、安装目录及 `node-path`。
- 应用访问被拒绝：检查聊天授权和系统权限；不要通过扩大授权绕过拒绝。
- Chrome 不可用：先检查 `lcu browser status`，再重新连接扩展。
- 回退：关闭设置中的 CUA 并新建对话；如改过 Chrome 原生宿主注册，恢复安装前的备份，
  再重新连接扩展。不要直接删除原有其他客户端的宿主注册。
