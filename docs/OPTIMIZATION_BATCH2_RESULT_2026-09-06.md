# 第二批优化实施记录

日期：2026-09-06。状态：三项已实施，未提交 Git。本批沿用现有配置加载、MCP 传输和审批系统，增加必要的校验与生命周期清理。

## 1. 项目配置不能借软链接提升权限，也不能替用户指定 LSP 程序

**原来的实际问题**：项目中的配置软链接指向目录外后，加载器可能把它当成可信配置，允许改变审批策略。项目的 `lsp.servers` 和 `features.exec_policy` 也没有被安全字段过滤覆盖。

**修复后**：按发现配置时的路径判断来源，项目软链接仍按项目配置过滤；忽略项目提供的 `lsp.servers` 和 `features.exec_policy`。模型等普通配置、LSP 开关及诊断偏好保留，用户配置的 LSP 命令保留。

**价值**：打开项目、开启代码诊断，不再意味着允许项目自行选择额外执行程序或关闭用户的命令策略。

**兼容变化**：项目自带的自定义语言服务器命令不会生效。日志会指出被忽略的字段、来源和用户配置迁移位置。请把命令放进实际使用的用户级配置，例如 `~/.deepseek/config.toml`：

```toml
[lsp.servers]
python = ["pyright-langserver", "--stdio"]
```

这只是迁移格式示例，仍应填写你原先使用且认可的程序。若使用 `DEEPSEEK_HOME`、`DEEPSEEK_CONFIG_PATH` 或优先级更高的 `~/.config/deepseek-tui/config.toml`，应编辑对应的实际用户配置；本次没有替你修改个人配置或安装语言服务器。

**验证**：普通/隐藏/自定义文件名的项目软链接均不能改变审批策略；用户 LSP 配置保留；测试经过配置加载、诊断管理器，到进程启动边界，确认选中的是用户命令。启动边界使用模拟替身，没有实际启动外部语言服务器。

## 2. MCP SSE 返回的通信地址必须同源

**原来的实际问题**：SSE 返回另一个网站的 endpoint 时，客户端会把原 headers 用于该地址的 POST；绝对地址和 `//host/path` 都可能触发。

**修复后**：解析地址后比较协议、主机和有效端口，拒绝跨源地址、用户信息、片段及非法/空地址；保留同源相对地址、大小写等价主机和默认端口。SSE GET/POST 不自动跟随重定向，避免自定义认证 headers 经重定向外发。发现失败立即结束连接建立，后续发送明确报错。

**价值**：服务返回错误或恶意地址时，阻止客户端把认证信息继续转交出去。

**兼容变化**：故意把 SSE GET 和 POST 部署在不同源，或依赖 HTTP 重定向的服务，需要改成直接配置最终同源地址。本次没有增加跨源例外开关，也没有禁止本机/内网 MCP。stdio 和 Streamable HTTP 的实现保持原行为。

**本机检查**：默认用户 MCP 配置中有两个 stdio 服务，不受此项限制；没有连接远程服务验证线上部署；仅输出传输类型统计，没有输出认证值。

**验证**：测试覆盖跨主机、协议降级、不同端口（含端口 0）、userinfo、非法协议、空 endpoint、正常相对地址、默认端口、GET/POST 重定向及初始 HTTP 错误。所有请求由离线模拟接收，使用假认证信息；被拒场景没有向另一源发出请求。

## 3. 审批不串请求，结束后清理

**原来的实际问题**：直接用模型的 `tool_call_id` 注册等待，同名调用会覆盖另一个等待；取消还会留下记录。卡片事件早于注册发出时，前端可能看到无法回答的审批。

**修复后**：HTTP 审批由服务器生成独立随机 ID，记录原线程、轮次和工具调用，后台任务另保留 task_id。先注册，再发卡片，最后在正常返回、取消或事件发送异常时清理。重复注册明确报错；重复回答和旧回答返回无效，不会影响新审批或覆盖已记住的结果。

轮次结束/中断只清理对应轮次的审批；不会顺便取消独立后台任务审批。线程卸载和服务关闭也清理等待；LRU 淘汰仅清理所属引擎的等待，保留独立后台任务审批。取消向执行层传播，不再伪装成一次普通拒绝后继续等待链路。

前端保存独立审批 ID 和原工具调用关联，提交使用服务器 ID；本轮已结束的卡片标为失效，异步到达的旧卡片通知也不会再显示，独立后台任务卡片仍可处理。

**价值**：多任务同名调用不会串审批，取消后不会留下能误解锁新请求的旧批准入口，也减少卡片卡住的情况。

**接口兼容要求**：事件和 pending 列表中的 `approval_id` / `id` 是提交地址使用的 ID；`tool_call_id` 是原工具调用关联，`turn_id` 是所属轮次。外部客户端不得再假设二者相同。

```json
{
  "approval_id": "appr_<server-generated-id>",
  "tool_call_id": "call_from_model",
  "turn_id": "turn_identifier"
}
```

回答时使用 `POST /v1/approvals/{approval_id}`。已失效或重复回答返回 `404 approval_not_found`。未添加固定五分钟超时；正常人工审批仍可持续等待。auto、单次批准和本会话记住的原有用途保留。
