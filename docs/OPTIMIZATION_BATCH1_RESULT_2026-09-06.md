# 第一批优化实施记录

本次实施方案中的三项明确错误修复，未重构任务管理器、审批系统或子代理架构。代码尚未提交 Git。

| 修复 | 原来的实际问题 | 现在的行为 | 代价与限制 |
|---|---|---|---|
| 后台任务默认目录 | 多个会话共享任务管理器时，省略 workspace 会使用管理器默认目录，可能查错或改错项目 | 新任务继承发起会话的实际目录；显式子目录和越界检查保留 | 依赖旧的错误默认目录的调用会改变目标；内部直接创建任务的默认值和已有任务保持原样 |
| 子代理补充指令 | 输入队列只在启动时读取，运行中发出的普通输入下一轮看不到 | 每轮请求前按顺序消费输入；结束前已有排队输入会进入下一轮；已消费输入在可取消操作前写入现有恢复记录 | 增加输入对应的上下文和一次恢复记录写入；下一轮生效，不能立即停止当前工具；不重置轮数上限，不实现 interrupt |
| 会话审批记忆 | 小写化和空白折叠让 `git branch -d` 与 `-D`、引号内不同文本共用批准 | 完整命令、实际工作目录、PTY 和后台模式共同生成固定长度指纹；审批界面与缓存使用一致标识 | 写法不同但效果相同的命令也可能重新询问；相同上下文和命令仍可复用；auto 行为不变 |

## 验证结果

新增 `tests/test_first_batch_regressions.py`，14 项通过。覆盖真实任务创建、共享管理器下的两会话目录隔离、显式子目录与软链接越界、多种命令碰撞、实际审批门禁重复询问/缓存复用、运行中输入、总结轮输入、消费前后取消恢复、输入顺序与不重复。

先在修复前执行初始复现集，得到 8 失败、2 通过；完成修复后扩展到 14 项并全部通过。验证不调用真实模型，也不执行测试中的删除命令。

相关审批、子代理、任务、Shell 超时和接口测试：228 通过、1 失败。
额外恢复测试：17 通过、1 失败。

两项未通过情况：

- `tests/test_subagent_result_fallback.py::test_visible_text_still_preferred_over_reasoning`：无标准总结标题时，思考文本覆盖可见结论。使用 Git HEAD 中修改前的子代理循环复测，同样失败；属于原有问题，本批未调整总结机制。
- `tests/contract/test_thread_resume.py::test_resume_thread_returns_detail`：隔离测试环境没有模型 API key，恢复接口构造客户端时抛出 `MissingApiKeyError`；未使用用户真实凭据完成该项验收。

新增测试与审批、任务文件的静态检查通过；其他改动文件的检查告警与 HEAD 基线一致，无新增告警。差异空白检查通过。没有执行全仓测试或真实模型端到端测试，因此不能承诺所有功能均无问题。
