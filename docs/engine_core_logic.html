这个文件是什么

Engine 类 = 三个 Mixin + 本体;本体管「回合编排」,Mixin 管「脏活」

类的构成 core.py:249

class Engine(ToolExecutionMixin,      # 工具执行:_execute_tool_calls / 审批 / 快照 (tooling.py)
           SessionMaintenanceMixin,   # 会话维护:压缩/L0修剪/cycle归档/长会话提醒 (maintenance.py)
           LifecycleLspMixin):        # 生命周期钩子:session_start/message_submit/turn_end + LSP 诊断 (lifecycle.py)

core.py 只保留构造、回合循环、会话编排;工具怎么执行、历史怎么压缩、钩子怎么跑都在兄弟文件里,通过继承「贴」到 Engine 身上。

设计动机(#756):父 turn 在直接子代理完成时恢复;后台(run_in_background)子代理的结果在 turn 结束后到达,靠空闲投递自动追一个隐藏 turn —— 用户无感知,模型总会收到回执。

上下文与成本管理

三级减压 + 真实计数 + 前缀缓存诊断 + 成本账本

三级减压(阈值依次升高,代价依次增大)

L0 修剪 — ≥ 50% 窗口
纯本地确定性裁剪老工具结果的正文,不调 LLM;每轮开头检查
重写压缩 — ≥ 75%(rewrite_ratio)
调摘要模型重写历史;摘要桥接放在 session_messages 首条 user 消息,system prompt 不动 → KV 前缀缓存稳定。失败冷却 5 轮
cycle 归档 — ≥ 90%(opt-in)
全量历史落盘归档,内存只留最近 8 条,重新规划继续;默认关闭

真实计数怎么来

  • last_real_input_tokens:每轮 StreamDone 的真实计费 input,消息只增不减所以单调 —— 压缩判断的主信号,零估算误差;turn 结束/取消时再兜底刷新一次
  • last_real_input_estimate:产生该真值的请求的本地估算 —— 之后每轮只加"估算增量",保留供应商校准又计入新工具结果
  • 切换模型 → 两个计数清零重测

前缀缓存击穿诊断 _log_prefix_break core.py:3074

变化点之前 = 可复用 token;model/tools/system 之一变了 → 前缀全失效(缓存根被换);之后全部按全价重计
