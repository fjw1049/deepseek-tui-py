🐛 浏览器「录制 / 回放 / 技能」问题汇总

基于 src/deepseek_tui/browser/ 实际代码核查 · 2026-10-14

设计边界 行为正确,但你期望的能力不存在 真实缺陷 确实该修 取舍说明 看起来像 bug,实际是刻意设计

一、你问的「不支持」—— 逐条确认

以下 3 条全部核实为不支持,且都是设计边界,不是故障。

设计边界L1 · 跨网站复用流程(淘宝录的,携程用不了)

现象在淘宝录的登录流程,拿到携程回放。
实际行为回放每一步都会先核对 URL / 选择器 / 元素特征(workflows.py:345-400),全部对不上,直接报错停住,一步都不会执行。
根因录制清单绑定具体页面的具体元素,是「一条流程一份剧本」,不是「学会登录」的抽象能力。
✅ 结论:不支持,且是故意的(防止在错误网站上执行错误操作)。想要携程的流程,就在携程再录一份。

设计边界L2 · 无自动触发,录制必须全手动

现象期望系统检测到重复操作时自动开始录制。
实际行为唯一入口是用户在前端点「开始/停止录制」按钮(browser_routes.py:248-259),且必须先接管浏览器控制权(workflows.py:68 强制校验)。不会在你浏览时偷录,agent 也无权决定录什么。
✅ 结论:不支持自动触发。什么时候录、录什么、何时停,全部由人手动决定。

设计边界L3 · 不会举一反三(无跨站点泛化)

现象期望 agent 从淘宝登录录制中"悟出"通用登录能力,以后任何网站都会登录。
实际行为技能里装的只是「参考数据 + 操作守则」(skills.py:45-95):agent 会照淘宝的路径操作,发现页面对不上时按守则停下询问,不会自己迁移到携程的页面结构上。
✅ 结论:不支持泛化。每份录制/技能只解决一个具体站点的具体流程。

二、核查中发现的真问题

以下是代码里确实存在、值得处理的缺陷和混淆点。

真实缺陷B1 · 两个「录制」同名,UI/文档必然误导用户

现象系统里有两个互不相干的"录制":
① run.recording = 截图拼 GIF,由 agent 工具 record_start/record_stop 控制(service.py:123-124, 1094)
② run.recorder = 流程录制器,由前端按钮控制(recording.py:190)
影响实测有效:真实用户(本次讨论)连问四轮才分清,前几轮全部理解偏(以为是视频、以为有逐张审核)。
建议UI/文档层面区分叫法,如「过程动图」vs「流程录制」;有余力再改代码字段名。

真实缺陷B2 · 录制只在当前会话内可回放,无明示

现象录制数据存在 artifact_root/<thread_id>/flows/(workflows.py:21-23),换一个会话就找不到这份录制。
实际行为跨会话复用的唯一途径是手动「生成技能」装进 .agents/skills/(skills.py:117)。
建议若产品预期"录制全局可用",这是功能缺口;若维持现状,需在 UI 上明示「录制仅本会话,跨会话请生成技能」。二选一,不能不说。

取舍说明D1 · 回放比人手慢(非 bug)

现象回放每步前多一次「观察+比对」(约 1 秒),30 步流程比人慢一倍以上。
设计意图用速度换安全:页面改版后宁可停下报错,也不点错按钮/提交错东西。
ℹ️ 维持现状即可;若未来要提速(如缓存观察结果),需重新评估误操作风险。

取舍说明D2 · 流程录制不保存任何真实输入值(非 bug)

现象录制里账号密码全是 {{占位符}},回放时要现场重新填。
设计意图mask-all 脱敏(recording.py:450),密码/敏感内容永不落盘;技能生成时连 example 值都会剥掉(skills.py:42-44)。
ℹ️ 安全特性,勿"修复"。副作用是每次回放都要重新提供凭据,属预期成本。

📌 一句话总结

你设想的「录一次、处处通用、自动触发」这套体验,当前系统三项都不支持——它的定位是「一条流程一份剧本,手动录制,同站复用」。真正需要修的只有 B1(命名混淆)和 B2(会话隔离无明示)两处 UX 问题。
