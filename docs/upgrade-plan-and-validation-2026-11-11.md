## 本轮决策与落地

| 项目 | 实现及边界 |
|---|---|
| shell 成功标准 | `exec_shell(expected_exit_codes=[0, 1])`；默认 `[0]`，严格校验整数 0–255。普通进程、PTY、显式后台和超时转后台共用原始标准。`task_output` 和完成通知带退出码、预期列表及成功状态。已运行进程不能临时更改标准；不解析命令猜测成功。 |
| 连续轮询 | 同一目标连续三次未完成，第四次起转为最多 60 秒等待，服从更小的调用/工具超时，并告知模型。独立任务 worker 不自动等待其他 durable task，避免占着唯一 worker。取消等待不取消任务。真正等待至少一秒的查询不受“重复无进展”忙轮询拦截；已有任务/轮次总时间与轮数预算仍有效。每次等待结束仍可能有一次模型请求，不能称 token 成本为零。 |
| 恢复上下文 | 现有逐请求 transcript 仍是权威来源。工具结果在压缩、落盘引用和 CUA 处理后发出内部事件，桌面端工具条目保存该模型消息，用于缺失 transcript 的兼容恢复；不再次压缩新记录。旧记录按线程模型压缩并保留原文落盘引用；孤立旧记录使用默认模型。没有通过条目恢复来冒充整段 transcript 的完整顺序。 |
| MCP 并发 | 每个服务器 `max_concurrency` 默认 1、范围 1–64，工具与资源 RPC 共用服务器信号量；不同服务器独立。显式可信只读 MCP 可进入并行批次。并行资格不等于免审批：交互 agent/yolo 保留原审批。限流约束本地在途调用；远端在客户端取消后继续执行的工作不由此保证。 |
| 历史投递凭据 | 自动化管理器初始化时执行版本化、可重入迁移。旧运行记录和新 HTTP trigger 记录中的企业微信目标改存引用；凭据集中在 `DEEPSEEK_HOME/secrets/delivery.sqlite3`（目录 0700、文件 0600）。改写前将原始字节加密备份，恢复密钥也在凭据库。中途失败不设置完成标记，可重试；无法解析的记录保留原文件并列入迁移报告的 `skipped`，不声称已清理；缺失引用拒绝投递，不能回退到另一默认目标。 |
| 凭据安全边界 | 这是减少重复凭据副本，不是 OS Keychain：集中库仍为当前用户可读的明文库；加密备份与库一起泄露时仍可解密。保留 API/日志读时脱敏，覆盖旧导入、损坏记录和迁移前数据；不采用“迁移完就删脱敏”的建议。本轮仅在临时目录验证迁移，用户实际记录在下次启动新版管理器时迁移。 |
| 非 UTF-8 全文件覆盖 | `write_file` 可替换 GBK 等文件，写入内容仍为 UTF-8。TUI 原有字节撤销保留；桌面端复用现有原始字节 sidecar 与事务恢复，保留初始字节和模式。无法取得可靠快照时拒绝覆盖；外部编辑冲突不自动覆盖。`edit_file` 仍是 UTF-8 文本替换，不猜编码。 |
| 搜索目录过滤 | 默认仍跳过 build/dist/依赖/缓存目录；结果注明遍历时实际跳过的目录数。显式指定这些目录可搜索其内部，跳过祖先的 gitignore，仍遵守目标目录内的 gitignore；仍保留 `.git` 和路径/敏感文件限制。这个计数不是未经遍历的全部嵌套目录总数。 |
| 无人值守 cron/trigger | 固定工具范围：读取/搜索/抓取、工作区写入、实际 OS 沙箱 shell、可信只读 MCP、受同样约束的子代理和 task_output。浏览器/CUA/交互提问及创建新 durable task 不开放。目录展示与执行入口都检查；需要人工授权的操作拒绝并计入 `needs_assistance`。普通用户启动的后台任务保留自己的权限规则。 |
| 网络策略 | 保持停用状态；不引入新审批开关。 |
| 旧工具入口 | 保留映射；每次使用输出不含参数的 `legacy_tool_used name=... replacement=... count=1` 日志。删除须有连续完整的观察窗口与兼容版本计划，不能凭仓库静态搜索认定无人使用。 |

MCP 配置示例（与现有 `mcpServers` 格式一致）：

```json
{"mcpServers": {"reports": {"command": "report-mcp", "max_concurrency": 2}}}
```

可信名单仍由用户级 `mcp_read_only_tools` 明确列出完整工具名，项目不能覆盖。

## 验证

所有新测试使用真实临时文件、进程、PTY、durable task manager、HTTP MCP 接收端或真实存储；模型响应采用确定性脚本，不产生付费模型调用。

- `tests/test_upgrade_exit_codes.py`：前台/后台/超时转后台 × 普通/PTY，预期非零成功、意外非零失败、非法参数不执行。
- `tests/test_upgrade_runtime.py`：自动等待、单 worker 豁免、取消等待、目录过滤/显式目录、凭据迁移/加密备份还原/磁盘失败重试/缺失引用、GBK 覆盖及冷启动 rewind、外部编辑冲突、快照失败不覆盖。
- `tests/test_upgrade_mcp_context.py`：真实 loopback HTTP MCP 并发上限，实际 Engine 文件工具结果与下一次模型请求比较，空文本/大文本按原记录恢复。
- `tests/test_upgrade_cron.py`：目录与执行层双重限制、伪造调用拒绝、工作区真实写入、越界拒绝、子代理继承限制、普通/PTY 无 OS 沙箱时不执行。
- 原有持续进展的 20 次查询测试显式采用 5ms 等待，避免因新的默认等待造成每次空等一分钟；另测真实 runtime wait 不误触发忙循环拦截。

全量结果以本报告末尾最终记录为准。首次全量发现并修复统一消息加载入口及孤立旧轮次缺失线程记录两个兼容问题。前端首次 2090/2091，图片缓存一项 5 秒超时，单独复跑 10/10，通过后继续单独运行全量，不修改或跳过失败用例。

## 性能取舍与暂缓项

对 100 条工具消息、合计 220 万字符（约 50.5 万估算 token）的 `estimated_input_tokens` 做五次 cProfile：热调用中位约 4.98ms；五次 JSON 序列化累计约 19ms；首调用的 tokenizer 初始化约 168ms。文本估算已有缓存。该本地合成样本不足以证明需要引入消息缓存失效机制，因此暂不加新缓存。复现脚本 `/tmp/upgrade-profile.py`，输出 `/tmp/upgrade-profile.log`；并非真实用户负载 P95。

stdout/stderr 字段有既有工具返回契约和后台工具测试消费；本轮不移除字段。大模块拆分不混入行为修复。公开 API 按版本退役、旧工具按实际日志观察；见 `tool-compatibility.md`。

**新增边界核对：** 普通 detached task/cron 的文件写入尚没有与桌面会话等价的持久文件撤销入口；现有任务 checkpoint 保存的是对话，不是文件原始字节。工作区限制不等于可撤销。本轮保留既有工作区写入能力，没有采用“这些写入已经都能撤销”的假设；任务级持久文件快照、归属冲突和恢复入口需要独立实现与验收。

未增加单自动化 `allow_browser` 开关：它需要单独的用户授权来源、会话隔离和子代理继承测试，不能由模型可写的普通参数扩大无人值守权限。现阶段默认关闭已生效。

跨平台安装、真实桌面交互和第三方渠道不是单元测试能替代的；按 `release-real-validation.md` 执行并记录证据。没有提供测试群/邮箱时，不向真实联系人发送验收消息。
