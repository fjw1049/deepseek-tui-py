# 图片视觉接入：实现与使用

更新：2026-09-09。本轮完成静态图片接入，保留原有文字主模型和多模型结构。代码已通过本地验证，未向真实付费模型发送图片。

## 如何使用

1. 更新后重启开发版桌面应用。
2. 若主模型支持图片，直接选择该模型，粘贴截图、拖入图片或通过附件选择图片，再发送问题。也可在输入中引用工作区内的 `@图片路径`。
3. 若继续使用文字主模型，在“设置 → 模型”中选择“视觉辅助模型”。该模型需要配置有效的服务地址和密钥，并由服务商明确支持图片输入。
4. 可以追问同一图片，或要求助手调用 `read_file` 裁剪查看局部。无需重复上传原图。

主模型收到原生图片，或者收到明确标注来源的视觉辅助观察；不会将本地路径或 Base64 字符串冒充图片输入。没有可用视觉路由时会报错，不静默丢弃图片。

桌面剪贴板和外部拖入支持 PNG、JPEG、WebP。工作区文件和 MCP 图片还支持静态 GIF、BMP、TIFF。动画图、视频、PDF 原生阅读不在本轮范围内；已有语音转文字功能保持独立。

## 已完成的链路

| 环节 | 行为 |
|---|---|
| 原图存储 | 原文件按 SHA-256 保存到 `$DEEPSEEK_HOME/media`，默认 `~/.deepseek/media`；会话保存引用，不嵌入 Base64 |
| 模型输入 | OpenAI Chat 兼容接口生成 `image_url`，Anthropic 接口生成图片内容块 |
| 工具图片 | `read_file` 和 MCP 图片保留为结构化内容；Chat 在完整工具结果批次之后附加有来源说明的图片，Anthropic 放入 `tool_result.content` |
| 视觉辅助 | 文字主模型使用显式配置的 `provider::model` 路由；原图交给辅助模型，返回的观察标明来源，有超时和成功结果缓存 |
| 局部检查 | `read_file(path="media:<asset_id>", crop=[x,y,width,height])`；坐标基于 EXIF 旋转后的原图，重新读原图可省略 `crop` |
| 持久化 | 保存用户和工具图片引用；恢复会话、上下文压缩后仍可按引用读取原图 |
| 导出备份 | 导出/备份携带对应会话引用的原图；导入校验文件内容与资产 ID，不夹带未被这些会话引用的旧图片 |
| 子任务 | 接收继承的图片、图片文件引用和图片工具结果；支持独立服务商路由，保留带服务商的模型标识 |
| 切换模型 | 更新主模型、后续子任务和任务配置；运行中的子任务保留原路由快照 |
| 计量 | 图片纳入本地上下文估算；辅助模型用量记为 `vision`，共享客户端并发时按当前任务归属 |

保持工具结果的原有 `content: string` 接口，新增独立的 `images` 列表，减少对文本工具、截断和持久化代码的连带改动。跨模块的规范消息仍然保留结构化图片。

## 配置

桌面设置会写入辅助模型选择。也可在现有配置中手工设置，示例中的服务商名称和模型 ID 需替换为实际配置：

```toml
[vision]
model = "visual-provider::actual-vision-model"
timeout_seconds = 90

[providers.visual-provider]
protocol = "openai" # 也支持 anthropic
base_url = "https://your-provider.example/v1"
api_key = "your-key"
model = "actual-vision-model"
image_input = true
image_max_side = 2048
image_request_bytes = 20971520

# 同一服务商同时提供文字和视觉模型时，可逐模型覆盖能力。
[providers.visual-provider.image_models]
"actual-text-model" = false
"actual-vision-model" = true
```

`image_models` 优先于服务商的 `image_input`。2026-09-10 已移除模型名称前缀判断：随后查询绑定官方服务地址、协议和完整模型 ID 的文档能力表；其后识别用户明确选择的辅助模型；其余保持未知并尝试原生输入。手动选择表示用户声明，不等于实测通过。官方 DeepSeek 视觉模型 `deepseek-v4-flash-vision-exp` 已登记为支持图片；第三方同名模型不继承官方结论。不会因一次普通网络错误就自动换模型。跨服务商辅助请求不继承主服务商的顶层密钥和地址。

能力来源保存在 `ImageCapability.source`，区分模型配置、服务商配置、官方文档、手动辅助模型选择、未知。能力依据：[DeepSeek 视觉文档](https://api-docs.deepseek.com/guides/vision/)。模型列表中的名称、请求返回 200、模型自称能看图，都不能单独证明图片理解能力。本轮尚未实现远端能力字段自动同步或实图探测按钮。

默认原图上限 32 MiB、解码上限 4000 万像素；发送版本默认最长边 2048 像素，优先 PNG，较大的发送版本转 JPEG。原图保持不变。图片请求预算默认 20 MiB，过大时先移除旧轮次发送副本中的图片并留下重读提示；当前轮次仍超预算则明确报错。图片 token 是本地估算，实际计费以服务商返回为准。

## 验证

- Python：372 项相关测试通过，覆盖图片读入、原图保留、裁剪、工具批次协议、模拟 HTTP 发送、会话恢复、连续压缩、导出导入、辅助路由、超时、计费隔离及已有多模型/子任务行为。
- 桌面端：29 项相关测试通过；生产构建通过。
- 修改的桌面核心文件 ESLint 通过；Python 新文件及修改行检查通过。
- 全量 TypeScript 类型检查未通过，但与改动前版本逐项对照后，错误相同，仅有代码插入造成的行号变化。本轮没有修复这些无关的既有类型问题。

## 尚未覆盖

- 真实服务商的可用性、图片理解质量和计费需要配置后的实际请求验证。本轮没有读取或修改用户密钥来发起付费测试。
- 未实现原生 Responses、Gemini 协议、视频/音频流理解、PDF 分页视觉输入。
- 图片资产的自动垃圾回收尚未实现，删除会话不会立即删除共享原图；桌面导入图片还会在工作区 `.deepseek/pastes` 留下附件文件。导出只选择被导出会话引用的资产。
- 自定义图片能力的逐模型开关目前通过配置文件设置；桌面端本轮提供辅助模型选择。
- 上下文窗口的显式覆盖现在对已知模型也生效，但现有窗口表仍按模型 ID 索引。同名模型在不同服务商配置不同窗口时，完整的服务商隔离仍需后续处理。

2026-09-10 能力判断修正：50 项能力、图片链路和多模型路由相关测试通过；未发起真实付费探测。
