# Goal 模式

Goal 是当前会话的持久目标。目标未完成时，运行时可在回合结束后续跑。完成记录、验收要求和未完成计划跨回合保存。本实现参考 Codex 公开设计；不宣称复刻其内部实现或达到同等模型成功率。

## 用户控制

```text
/goal 修复登录流程；正确密码可登录，错误密码被拒绝，相关回归测试通过
/goal status
/goal pause
/goal resume
/goal reopen
/goal cancel
/goal budget tokens 20000 turns 12 seconds 900
```

`pause` 中断并保留工作，`resume` 继续，`reopen` 重开已完成目标并清除旧验收证据，`cancel` 清除记录。恢复和预算修改仅由用户命令/UI 执行；模型不再获得 SetGoalBudget 工具，也不能用 UpdateGoal(active) 自行恢复。模型收到明确自然语言预算时，应引导用户通过预算命令设置，不能自行扩大额度。

预算是总额度，不是追加量。token 计输出 token，不是总费用。时间预算修改会唤醒当前计时器重新计算；回合中首次设置同样生效。修改 token 预算不会因为正在执行最后一个获准回合就提前停止。Workbench 的“保存预算并恢复”发出一个绑定目标 ID 的请求；切换会话后，迟到响应不会覆盖新会话。

## 验收要求和执行计划

创建时自动保留完整 objective 和用户提供的 completionCriterion 作为必须验收的要求。模型可通过 `UpdateGoal(status="requirements", requirements=[...])` 添加从原请求提取的验收项；已有要求不可删除或覆盖。验收项显示在目标详情里。

checklist 仍用于执行计划，和验收要求分开存储。删除开放计划项不会使其从 Goal 消失。确实放弃某种实现路线时，可以取消相应步骤，但完成审计必须说明替代路线为什么仍覆盖用户要求；取消计划不等于取消要求。若用户明确改变目标范围，使用替换目标流程，建立新目标。

## 完成申请

模型调用 `UpdateGoal(status="complete")` 时必须提供：

- `reason`：完成说明。
- `evidence`：真实、成功、已结束的验证工具调用 ID。
- `audit.checks`：每个验收要求的 `requirement_id`、`explanation` 和 `evidence`。
- `audit.failure_resolutions`：尚未被同参数成功重跑取代的失败记录，说明失败原因、替代验证和证据。不能通过后续无关成功静默忽略失败。
- `audit.plan_adjustments`：取消计划步骤的 ID 和保持需求覆盖的理由。

`GetGoal` 返回要求 ID、验证记录和保存的审计。示例：

```json
{
  "status": "complete",
  "reason": "登录行为已实现并验证",
  "evidence": ["call-tests"],
  "audit": {
    "checks": [
      {"requirement_id": "objective", "explanation": "登录成功及错误密码拒绝用例均通过", "evidence": ["call-tests"]}
    ]
  }
}
```

若另外添加了验收要求或 completionCriterion，也必须逐项列入 checks。运行时拒绝缺项、开放计划、无效证据、未解释的失败/取消项，以及仍运行的子 Agent 或附属于当前工作的 Shell 进程。用于开发服务的明确 detached 进程不阻止结束，但其运行中结果不能当作已完成验证。

完成校验和状态提交统一在 GoalService.mark_complete 中执行，内部调用也不能跳过检查。完成前再次检查实际时间和 token 预算。最近的普通证据保留 80 条；未被取代的失败记录单独保留，不因历史滚动而消失。

## 证据时效

执行工具前后计算工作区内容指纹，在提交完成前再次核对。捕获到文件变化就使旧验证版本失效；工具执行期间工作区发生变化，该次结果不能充当稳定验证。这样覆盖允许的 Shell 产物写入、外部编辑器以及子 Agent 的工作区变化。项目已有的 Shell 直接源码写入限制继续适用。

Git 工作区覆盖 tracked 文件和未忽略的 untracked 文件；非 Git 工作区遍历文件并排除 `.git`、`.deepseek`、虚拟环境、node_modules 和常见缓存。无法读取稳定快照时拒绝完成，不假装验收成功。

当前不覆盖 Git 忽略产物的内容变化、工作区外的文件、符号链接目标和远端服务状态；含 submodule 目录的快照目前会拒绝验证。这些场景需后续增加明确的产物范围支持，不能把本机制理解为全系统文件监控。模型仍须针对实际产物和行为重新检查。

## 停止、恢复与竞态

自动续跑没有工作工具调用时暂停。同样的工具参数、输出、文件版本、计划和要求连续重复三次而没有进展，也暂停并给出原因。进行中的工具等待不因重复输出触发该规则；输出变化视为进展。这是保守的循环保护，不是语义进展评分。

恢复未完成目标时进入 paused，并使旧证据版本失效；要求、计划和失败记录保留。恢复损坏证据时作废无效记录，非法计划状态按 pending 处理，不能据此完成。

异步启动自动续跑时绑定目标 ID，预约回合时和 Engine 消费消息时再次校验。暂停/替换后的排队续跑不会调用模型。用户暂停再恢复后，旧模型 Goal 工具调用失效，旧回合的取消事件不会撤销新恢复操作。自动续跑发生线程占用冲突时，不再暂停获胜的用户回合。

这些保护不等于完整的跨进程用户消息优先队列；前端待发送消息和服务端队列的统一仲裁、队列推进崩溃窗口仍需专项强化。

## 验证与实际效果边界

运行 `tests/goal/`，尤其是 `test_production_regressions.py`，验证失败后引用无关成功、删改计划、缺少需求覆盖、超时完成、模型扩额、真实 Shell 写入、外部编辑、恢复、重复空转和旧回合取消等负例及合法完成正例。`test_hooks.py` 包含启动竞态与预算命令集成测试。Workbench 测试覆盖会话切换、迟到响应和验收展示。

反例脚本 `docs/goal-production-probes.py` 可在升级后重新运行；`goal-production-probes-results.json` 是升级前历史结果，`goal-production-probes-results-after.json` 是升级后结果。二者不能当作真实模型成功率。

机械检查可以验证引用、覆盖、状态和时效，不能证明模型写的说明一定真实，也不能保证它把自然语言请求完整拆成验收项。当前没有独立语义裁判，没有完成真实模型任务集和 Codex 同任务对照。上线评估应由外部验收判断真实完成率、错误完成率和错误阻塞率，不能拿 Goal 自己的 complete 状态作真值。
